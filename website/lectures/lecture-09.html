3. Searching for Text

3.1 Text Indexes

  • Text indexes are required when using the $text query operator to search string content.
  • A text index can include any field whose value is a string (e.g., comments) or an array of string elements.
  • Create a text index with createIndex():
db.blogs.createIndex( { comments: "text" } )
  • A collection can have at most one text index. Note: a single text index can include multiple fields.
  • Remove an index with the dropIndex() method.

Walkthrough:

  1. The index specification { comments: "text" } uses the string "text" instead of 1/-1 (compare ascending/descending indexes in Lecture 14).
  2. MongoDB responds with the auto-generated index name comments_text (seen in the slide screenshot).
  3. Only the comments field is searchable with $text now; title is not covered.

Modern MongoDB (slide note): MongoDB Search provides more advanced full-text search and is recommended for new full-text search applications. The $text operator remains supported and is useful for learning basic MongoDB text indexes.

Example (added for clarity) — A Multi-Field Text Index

db.blogs.createIndex( { title: "text", comments: "text" } )

This is still one text index (allowed) but covers two fields. Trying to create a second, separate text index on the same collection would fail — to change the indexed fields you must drop the old text index first (db.blogs.dropIndex("comments_text")).

3.2 Searching for a Word — $text and $search

Task: find documents with the word "big" in the comments field.

var c = db.blogs.find( { $text: { $search: "big" } } )
while ( c.hasNext() )  printjson( c.next() )

Result (from the slide screenshot):

{ _id: ObjectId("6511c4e158d33a1abbda5ebb"),
  title: 'NoSQL',
  likes: 400,
  comments: 'NoSQL databases were invented for Big Data' }

Walkthrough:

  1. { $text: { $search: "big" } } — the filter document uses the $text operator with a $search string.
  2. Only document 1 contains the word big — it appears as "Big" (capital B), and it still matches because $text searches are case-insensitive by default.
  3. Cursor loop: find() returns a cursor held in the variable c. c.hasNext() is true while documents remain; c.next() fetches the next one; printjson() prints it. (The same pattern is used for shell functions in Section 4.)

3.3 Searching for Several Words — OR Semantics

Task: documents containing "big" or "data" in comments.

var c = db.blogs.find( { $text: { $search: "big data" } } )
while ( c.hasNext() )  printjson( c.next() )

Result (from the slide screenshot): two documents

{ title: 'NoSQL', likes: 400, comments: 'NoSQL databases were invented for Big Data' }
{ title: 'Neo4j', likes: 150, comments: 'Neo4j can store social networks data' }

Walkthrough:

  1. A space-separated list of terms in $search is treated as logical OR — a document matches if it contains any of the words.
  2. Document 1 contains both "Big" and "Data"; document 6 contains "data" only. Both match.
  3. Why don't the "database" documents match "data"? $text matches whole (stemmed) words, not substrings: "database" is a different word from "data".

Additional Examples (added for clarity — standard $text features, not on the slides)

db.blogs.find( { $text: { $search: "\"big data\"" } } )   // exact PHRASE: both words together
db.blogs.find( { $text: { $search: "database -Neo4j" } } ) // minus sign EXCLUDES a term

Use escaped double quotes for a phrase, and a leading - to exclude a word.

3.4 Wildcard Text Indexes

  • To allow text search on all fields with string content, use the wildcard specifier $**:
db.collection.createIndex( { "$**": "text" } )
  • MongoDB then indexes every field containing string data in every document.
  • Useful for highly unstructured data where it is unclear which fields to include, or for ad-hoc querying.

Caution (slide note): use wildcard text indexes cautiously — they can increase index size and hurt insert/update performance. Targeted text indexes are preferable when the searchable fields are known.

Example (added for clarity)

On blogs, db.blogs.createIndex({ "$**": "text" }) would index both title and comments, so $search: "Neo4j" would now match on titles too. That is convenient while exploring unknown data, but for a production blog search you would index just comments (and perhaps title).

3.5 Text Search in the Aggregation Pipeline

  • Text search in a pipeline uses the $text operator in the $match stage.
  • Restrictions:
    1. The $match stage containing $text must be the FIRST stage in the pipeline.
    2. A text operator can only occur once in the stage.
    3. The text operator expression cannot appear in $or or $not expressions.

Example (from the slides): search for "NoSQL" and total the likes of the matching documents.

db.blogs.aggregate( [
    { $match: { $text: { $search: "NoSQL" } } },
    { $group: { _id: null, totalLikes: { $sum: "$likes" } } }
] )

Result:

{ "_id": null, "totalLikes": 550 }

Step-by-step trace (against the Section 2 table):

  1. $match with $text — keeps documents whose indexed field (comments) contains "NoSQL":
    • Doc 1 "NoSQL databases were invented…" → 400 likes
    • Doc 2 "MongoDB is a NoSQL database" → 100 likes
    • Doc 5 "Neo4j is a NoSQL database" → 50 likes
    • (The title: "NoSQL" is irrelevant here — only the comments field is text-indexed.)
  2. $group with _id: null — one single group for all surviving documents (no grouping key).
  3. totalLikes: { $sum: "$likes" } — adds the likes values: 400 + 100 + 50 = 550 . Note "$likes" — the $ prefix refers to the value of the field in each document.

4. Mongo Shell (Client) Functions

The shell is a JavaScript environment, so you can define your own functions to avoid retyping long commands.

4.1 Example 1 — A Function That Creates Data

function insertData( dbName, colName, num )
{
    const col = db.getSiblingDB(dbName).getCollection(colName);
    for ( i = 0; i < num; i++ )
    {   col.insertOne( { x: i } );   }
    print( col.countDocuments() );
}

Walkthrough:

  1. Parameters: database name, collection name, and the number of documents to insert.
  2. db.getSiblingDB(dbName) — the JavaScript equivalent of use dbName (Lecture 14, "helpers vs JavaScript"); .getCollection(colName) gets the collection by name (works for any name held in a variable).
  3. for loop — inserts num documents { x: 0 }, { x: 1 }, …, { x: num-1 }.
  4. col.countDocuments() — returns the number of documents in the collection; print() displays it.
  5. Call: insertData("mydb", "testCollection", 20) → inserts 20 documents and prints 20 (if the collection started empty).

4.2 Storing Functions in .mongoshrc.js

  • A function can be stored in the file .mongoshrc.js for future use.
  • Location: the user's home folder (slide example: C:\Users\UserName).
  • The file's contents are loaded when the shell starts, so your functions are available in every new session.

4.3 Example 2 — Wrapping an Aggregation in a Function

Recall (Lecture 15): compute the total likes for the title 'Neo4j':

db.blogs.aggregate( [
    { $match: { title: "Neo4j" } },
    { $group: { _id: "$title", num_likes: { $sum: "$likes" } } }
] )
  • Problem (slide): "Not nice to have to type this query whenever the aggregate is needed." → put it in a function.

Function definition in .mongoshrc.js:

function computeTotalLikes( dbName, colName, blogTitle )
{
    var col = db.getSiblingDB(dbName).getCollection(colName);
    var res = col.aggregate( [
        { $match: { title: blogTitle } },
        { $group: { _id: blogTitle, num_likes: { $sum: "$likes" } } }
    ] );
    while ( res.hasNext() )  printjson( res.next() );
}

Function call and result (slide screenshot):

db> computeTotalLikes("db", "blogs", "Neo4j")
{ _id: 'Neo4j', num_likes: 450 }

Walkthrough:

  1. The hard-coded database, collection and title become parameters (dbName, colName, blogTitle) — one function now works for any title.
  2. $match: { title: blogTitle } — the JavaScript variable is dropped straight into the pipeline.
  3. _id: blogTitle — the group key is the title value (the earlier version used "$title", a field reference; here the variable's value is used, so the output _id is 'Neo4j').
  4. col.aggregate(...) returns a cursor, so the while (res.hasNext()) printjson(res.next()) loop prints each result.
  5. Trace: Neo4j documents have likes 50 + 150 + 250 = 450 (docs 5, 6, 7).

Note (slide detail): in the call, the first argument is the database name ("db" in the demo — a database that happens to be named db), not the shell's db object.

Example (added for clarity)

computeTotalLikes("db", "blogs", "MongoDB") → { _id: 'MongoDB', num_likes: 300 } (100 + 150 + 50).

4.4 Why Use Shell Functions? (summary, added for clarity)

Benefit Explanation
Reuse Write the query once; call it with different arguments.
Fewer typing errors Long pipelines are error-prone to retype.
Persistence Saved in .mongoshrc.js, loaded at every shell start.
Familiar analogy Similar to stored procedures in relational DBMSs — but these run client-side in the shell, not on the database server (hence "client functions").

5. Java & MongoDB Applications

5.1 The MongoDB Java Driver

  • The MongoDB Java Driver provides an API for Java applications to access MongoDB.
  • It provides synchronous and other Java APIs for interacting with MongoDB.
  • Add the driver to the project using Maven or Gradle.
  • Core classes:
    • MongoClient — the connection to the MongoDB server/cluster.
    • MongoDatabase — a database obtained from the client.
    • MongoCollection — a collection obtained from the database.
  • (The slides refer to a demo video showing how to set up and test a Java application.)

5.2 Dependency Management (Maven / Gradle)

  • Current MongoDB documentation recommends Maven/Gradle dependency management rather than manually adding an old JAR file (which the earlier demo video does).
  • Current Maven setup:
<dependency>
    <groupId>org.mongodb</groupId>
    <artifactId>mongodb-driver-sync</artifactId>
</dependency>
  • The MongoDB driver BOM (Bill of Materials) manages the version, so the version number does not need to be written in the dependency.

5.3 Demo and Further Reading

  • Demo: follow the demo to learn how to create and test a Java application that uses a MongoDB database.
  • Further reading: the MongoDB Java Driver documentation — mongodb.com/docs/drivers/java/sync/current/get-started/

Illustrative Example (added for clarity — NOT from the slides)

A minimal sketch tying the three core classes together (using the blogs collection):

import com.mongodb.client.*;
import org.bson.Document;
import static com.mongodb.client.model.Filters.eq;

public class BlogDemo {
    public static void main(String[] args) {
        try (MongoClient client = MongoClients.create("mongodb://localhost:27017")) {
            MongoDatabase     db    = client.getDatabase("db");
            MongoCollection<Document> blogs = db.getCollection("blogs");

            blogs.insertOne( new Document("title", "Neo4j")
                                 .append("comments", "Neo4j is great")
                                 .append("likes", 10) );

            for ( Document d : blogs.find( eq("title", "Neo4j") ) )
                System.out.println( d.toJson() );
        }
    }
}

Reading it: MongoClient connects → getDatabase gives a MongoDatabase → getCollection gives a MongoCollection<Document> → insertOne / find mirror the shell commands. A Document is the Java representation of a BSON document. Compare with the JDBC code from the OODBMS lectures: here no SQL strings and no manual row-to-object translation are needed, which reduces the impedance mismatch. Treat this sketch as an aid only and check it against the driver documentation.

7. Questions & Memo

(Use the blogs table in Section 2 for all tracing questions; assume a text index exists on comments only.)

Section 3 — Text Search

Q1: What is required before you can use the $text operator, and how do you create it for the comments field?

A1: A text index on the field(s) being searched: db.blogs.createIndex({ comments: "text" }). Without one, $text queries fail.

Q2: How many text indexes can a collection have? Can a text index cover more than one field?

A2: At most one text index per collection, but that single index may include multiple fields. (An index is removed with dropIndex().)

Q3 (Code Tracing): What does db.blogs.find({ $text: { $search: "big" } }) return, and why does it match although the text contains "Big" with a capital letter?

A3: Only document 1 ("NoSQL databases were invented for Big Data", 400 likes). $text searches are case-insensitive by default, so "Big" matches "big".

Q4 (Code Tracing): What does { $search: "big data" } return, and what logical operator is used between the words?

A4: Two documents: doc 1 (…Big Data) and doc 6 (Neo4j can store social networks data). Multiple space-separated words are combined with OR — a document matching either word is returned.

Q5: Why does the search for "data" not return documents such as "MongoDB is a NoSQL database"?

A5: $text matches whole words (after stemming), not substrings. "database" is a different word from "data", so those documents don't match.

Q6: What is a wildcard text index, when is it useful, and what is the drawback?

A6: Created with db.collection.createIndex({ "$**": "text" }); it indexes every field containing string data. Useful for highly unstructured data or ad-hoc querying when the searchable fields are unknown. Drawback: larger index size and slower inserts/updates, so targeted text indexes are preferable when the fields are known.

Q7: List the three restrictions on using $text in the aggregation pipeline.

A7: (1) The $match stage containing $text must be the first stage of the pipeline. (2) A text operator can appear only once in the stage. (3) The text expression cannot appear in $or or $not expressions.

Q8 (Code Tracing): Trace the result of:

db.blogs.aggregate([
  { $match: { $text: { $search: "NoSQL" } } },
  { $group: { _id: null, totalLikes: { $sum: "$likes" } } } ])

A8: $match keeps documents whose comments contain "NoSQL": doc 1 (400), doc 2 (100), doc 5 (50). $group with _id: null makes one group; $sum of likes = 400 + 100 + 50 = 550. Result: { "_id": null, "totalLikes": 550 }.

Q9 (Code Writing): Write an aggregation giving the average likes of the blogs whose comments contain the word "database".

A9:

db.blogs.aggregate([
  { $match: { $text: { $search: "database" } } },
  { $group: { _id: null, avgLikes: { $avg: "$likes" } } } ])

Trace: with English stemming, "database" also matches "databases", so the matched documents are 1, 2, 3, 5 and 7 (likes 400, 100, 150, 50, 250) → average = 950 / 5 = 190. (This relies on stemming behaviour — confirm on your own instance.)

Q10: Why does the $text aggregation stage have to come first?

A10: Because text search relies on the text index, which MongoDB can only use at the start of the pipeline, where the stage reads directly from the collection. Later stages work on transformed in-memory documents with no index.

Section 4 — Shell Functions

Q11: Where can you store your own shell functions so they're available every time the shell starts, and why do this?

A11: In the .mongoshrc.js file (e.g., in C:\Users\UserName), whose contents are loaded when the shell starts. It avoids retyping long commands and lets you reuse them.

Q12 (Code Tracing): Explain what insertData("mydb", "testCollection", 20) does and prints.

A12: It gets testCollection in mydb (via getSiblingDB(...).getCollection(...)), inserts 20 documents { x: 0 } … { x: 19 } in a loop, then prints the document count (countDocuments()), which is 20 if the collection started empty.

Q13 (Code Tracing): What does computeTotalLikes("db", "blogs", "Neo4j") output? Show the working.

A13: { _id: 'Neo4j', num_likes: 450 }. $match selects the Neo4j documents (likes 50, 150, 250); $group sums them: 50 + 150 + 250 = 450.

Q14 (Code Writing): Write a shell function countByTitle(dbName, colName, blogTitle) that prints the number of blog documents with a given title.

A14:

function countByTitle( dbName, colName, blogTitle )
{
    var col = db.getSiblingDB(dbName).getCollection(colName);
    print( col.countDocuments( { title: blogTitle } ) );
}

countByTitle("db", "blogs", "Neo4j") → 3.

Q15: Why use while (res.hasNext()) printjson(res.next()) after aggregate() inside a function?

A15: aggregate() returns a cursor, not an array. The loop iterates through the cursor (hasNext() / next()) and prints each result document with printjson.

Q16: In computeTotalLikes, why is _id: blogTitle used rather than _id: "$title"?

A16: Both give the same group key here: "$title" is a field reference read from each document, while blogTitle is the function parameter's value. Since $match already restricts to one title, the parameter value can be used directly.

Section 5 — Java and MongoDB

Q17: Name the three main Java classes used to interact with MongoDB and what each represents.

A17: MongoClient — the connection to MongoDB; MongoDatabase — a database; MongoCollection — a collection of documents.

Q18: How should the MongoDB Java driver be added to a project according to current documentation, and why?

A18: Via Maven or Gradle dependency management (e.g., org.mongodb:mongodb-driver-sync), with the driver BOM managing the version, rather than manually adding an old JAR — it handles dependencies and versions automatically.

Q19: Compare accessing MongoDB from Java with the JDBC approach from the OODBMS lectures (impedance mismatch).

A19: With JDBC, Java embeds SQL strings and receives generic ResultSet rows that must be manually mapped to objects (the impedance mismatch). With the MongoDB Java driver, data is exchanged as documents (JSON/BSON-like objects) via Document and MongoCollection methods (insertOne, find), which maps far more naturally onto Java objects — no SQL strings and less translation.

Example — Average grade of second-year students by course

MongoDB Shell

db.students.aggregate([
    { $match: { year: 2 } },
    { $group: {
        _id: "$course",
        average: { $avg: "$grade" }

])

students.aggregate(Arrays.asList(
    match(eq("year", 2)),
    group("$course", avg("average", "$grade")),
    sort(descending("average"))
));

The logic and pipeline order are identical. Only the syntax changes.

import static com.mongodb.client.model.Aggregates.*;

When Java methods have the same name (such as sort()), the surrounding context or an explicit class name such as Aggregates.sort(...) can help distinguish them.

11. Can you use MongoDB syntax directly in Java?

Yes. The Java driver also supports BSON documents, so you don't always need to use the helper methods.

For example, these are equivalent:

Java using predefined methods

students.find(gt("age", 20));

Java using MongoDB-style BSON

students.find(
    Document.parse("{ age: { $gt: 20 } }")
);

The second option looks almost identical to mongosh. It is still executed through the Java driver, not through the MongoDB shell.
