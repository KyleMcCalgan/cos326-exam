2. Graph Theory — The Mathematical Perspective

  • Graph theory is a branch of discrete mathematics (covered in WTW 285).
  • Distinguished by its geometric approach to the study of various objects.
  • The principal object of the theory is a graph and its generalisations.

2.1 Formal Definition

  • A graph is denoted G = (V, E), where:
    • V = a set of vertices.
    • E = a set of edges.
  • Each edge is a tuple (vᵢ, vⱼ) where vᵢ, vⱼ ∈ V.
  • A third component w can be added to represent a weight: (vᵢ, vⱼ, w).
  • A subgraph G′ of G = (V, E) consists of a subset of vertices and a subset of edges connecting those vertices.

2.2 Key Terms

Term Meaning
Vertex (also "node") Can have a name, aka the "key"; may also hold additional information.
Edge (also "arc") Connects two vertices to show a relationship between them. Edges may be one-way or two-way.
Directed graph (digraph) A graph in which all edges are one-way.
Weight Shows a cost to go from one vertex to another (e.g., in a road graph, the distance between two cities).
Path A sequence of vertices connected by edges.
Cycle (in a directed graph) A path that starts and ends at the same vertex, with no repeated vertices except the first/last.

Formal representation: V = {V0, V1, V2, V3, V4, V5} and E = {(V0,V1,5), (V0,V5,2), (V1,V2,4), (V2,V3,9), (V3,V4,7), (V3,V5,3), (V4,V0,1), (V5,V2,1), (V5,V4,8)}.

Step-by-step reading:

  1. Directed: every edge has an arrowhead, so V0 → V1 does not imply V1 → V0.
  2. A path: V0 → V5 → V2 → V3 is a sequence of vertices joined by edges; its total weight is 2 + 1 + 9 = 12.
  3. A cycle: V0 → V5 → V4 → V0 starts and ends at V0 with no other repeated vertex; weight 2 + 8 + 1 = 11.
  4. Cheapest route V0 → V4: via V5 directly = 2 + 8 = 10; via V5 → V2 → V3 → V4 = 2 + 1 + 9 + 7 = 19 → the direct route via V5 is cheaper.
  5. A subgraph: e.g., vertices {V0, V1, V2} with edges {(V0,V1,5), (V1,V2,4)}.

3. Graph Data Structure — The Computational Perspective

  • The Graph Abstract Data Type (ADT) (part of the CS curriculum) supports these operations:
Operation Purpose
Graph() Creates a new, empty graph.
addVertex(vert) Adds an instance of Vertex to the graph.
addEdge(fromVert, toVert) Adds a new, directed edge connecting two vertices.
addEdge(fromVert, toVert, weight) Adds a new, weighted, directed edge connecting two vertices.
getVertex(vertKey) Finds the vertex in the graph named vertKey.
getVertices() Returns the list of all vertices in the graph.
in Returns True for vertex in graph if the vertex is in the graph, False otherwise.

📌 Coding Example (added for step-by-step clarity)

g = Graph()                # 1
g.addVertex("V0")          # 2
g.addVertex("V1")          # 3
g.addEdge("V0", "V1", 5)   # 4  weighted, directed edge V0 -> V1
print("V1" in g)           # 5  True
print(g.getVertices())     # 6  list of all vertices

Step-by-step walkthrough:

  1. Graph() creates an empty graph; 2–3. two vertices are added, each identified by a key (its name).
  2. addEdge("V0","V1",5) adds the directed, weighted edge (V0, V1, 5) — it does not create V1 → V0.
  3. "V1" in g evaluates to True; getVertices() returns the vertex list.

4. Graph Database Concepts

  • Recall the classification of NoSQL databases: (1) key-value stores, (2) document databases, (3) wide-column stores, (4) graph databases (and time series).
  • A graph database stores data using a few simple concepts:
Concept Meaning
Nodes Graph data objects (records).
Relationships Edges which connect nodes (objects).
Properties Named data values — attributes expressed as key-value pairs.
  • Graph databases represent entities and the relationships between them as a graph.
  • In Neo4j: nodes represent entities; relationships represent connections; properties describe nodes and relationships.

4.1 Primary Uses and Example DBs

  • Uses: representing social networks, generating recommendations, conducting forensic investigations.
  • Example DBs: Neo4j, Amazon Neptune, TigerGraph, ArangoDB.

4.2 Graph Theory ↔ Graph Database Terminology (added for clarity)

Graph theory Graph database (Neo4j)
Vertex / node Node (record)
Edge / arc Relationship
Edge weight A property on the relationship
Vertex "additional information" Properties (+ labels)
Directed edge Relationship direction (start node → end node)

5. The Neo4j Graph Database

  • Neo4j is a graph database management system (GDBMS) based on the graph theory model.
  • Developed primarily using Java/JVM technologies.
  • Stores data as nodes, relationships and properties.
  • Uses Cypher as its declarative graph query language.
  • Provides APIs/drivers for application development.
  • Available in Community Edition and Enterprise Edition.
  • Community Edition is licensed under GPL v3.

5.1 Nodes

  • The simplest graph has just a single node with some named values called properties.
  • A node is the name for a data record in a graph.
  • Data is stored as properties — simple key/value pairs, e.g., name: "Thandi", from: "Durban".

Labels

  • Labels are used to associate (group) a set of nodes — e.g., all people nodes get the label Person.
  • A node can have zero or more labels.
  • Labels do not have any properties.
  • Neo4j supports a flexible schema:
    • Nodes can have different sets of properties.
    • Labels classify nodes.
    • Constraints and indexes can be defined when data integrity and efficient lookup are required.

📌 Example — Slide figure: a Node with label Person

(:Person { name: "Thandi", from: "Durban" })
  • One node, two properties, one label — the simplest possible graph.

5.2 Relationships

  • Relationships connect nodes in the graph — "the real power" of a graph database is in connected data.
  • Relationships describe how records are related.
  • A Neo4j relationship has:
    1. A start node.
    2. An end node.
    3. Exactly one relationship type (e.g., FOLLOWS).
    4. An optional set of properties.
    5. A direction.

📌 Worked Example — Slide figure: the FOLLOWS relationship

Nodes: Thandi (Durban), Neo (Cape Town), Johan (Pretoria).

  • Thandi FOLLOWS Neo and Thandi FOLLOWS Johan.
  • Johan FOLLOWS Thandi.

Step-by-step reading:

  1. Three Person nodes, each with name and from properties.
  2. Three directed FOLLOWS relationships (three arrows).
  3. Direction matters: Johan follows Thandi, but Thandi also follows Johan requires its own, separate relationship; nobody follows Neo back — Neo has no outgoing FOLLOWS.

5.3 Relationship Properties

  • Relationship properties store attributes of the relationship between two nodes.
  • In a property graph, relationships are data records (objects) that can also contain properties.

📌 Worked Example — Slide figure: FOLLOWS with since

Relationship since
Thandi FOLLOWS Neo 2009
Thandi FOLLOWS Johan 2012
Johan FOLLOWS Thandi 2010 
flowchart LR
  Thandi["Person: Thandi<br/>from: Durban"]
  Neo["Person: Neo<br/>from: Cape Town"]
  Johan["Person: Johan<br/>from: Pretoria"]
  Thandi -->|FOLLOWS, since 2009| Neo
  Thandi -->|FOLLOWS, since 2012| Johan
  Johan -->|FOLLOWS, since 2010| Thandi
  • The since value lives on the relationship, not on either node — because it describes the connection (when it began), not a person.

7. Cypher — Neo4j's Query Language

  • Cypher is Neo4j's graph query language:
    • Purpose-built for working with graph data.
    • Uses patterns to describe graph data.
    • Uses familiar SQL-like clauses.
    • Is declarative (like SQL) — it describes what to do, not how to do it.

7.1 Pattern Syntax Cheat-Sheet (consolidated from the slides)

Symbol Meaning
( ) A node
psT:Person Variable psT + label Person
{ name: "Thandi" } Properties (key-value pairs)
-[ ]-> A directed relationship (arrow shows direction)
[r] A relationship stored in variable r
[:FOLLOWS] A relationship of type FOLLOWS
[:FOLLOWS {since: 2012}] Relationship with a property

7.2 CREATE — Creating a Node (from the slides)

CREATE (psT:Person { name: "Thandi", from: "Durban", hobby: "singing" })

Step-by-step walkthrough:

  1. CREATE clause — used to create data.
  2. ( ) parentheses — indicate a node.
  3. psT:Person — a variable psT (to refer to the node later in the query) and the label Person.
  4. { } — adds the properties name, from, hobby to the node.
  5. Result (slide screenshot): "Created 1 node, set 3 properties, added 1 label."

7.3 MATCH — Finding Nodes (from the slides)

MATCH (psT:Person)
WHERE psT.name = "Thandi"
RETURN psT;

Step-by-step walkthrough:

  1. MATCH — specifies a pattern of nodes and relationships to find.
  2. (psT:Person) — a single-node pattern with label Person; every match is assigned to the variable psT.
  3. WHERE psT.name = "Thandi" — constrains the results; compares the name property to "Thandi" (dot notation: variable.property).
  4. RETURN psT — requests the particular results to output.
  5. Result: the one Thandi node; clicking it in the graph view shows its properties (name, from, hobby).
  6. SQL analogy: SELECT * FROM Person WHERE name = 'Thandi';

7.4 CREATE — Many Nodes and Relationships at Once (from the slides)

MATCH (psT:Person) WHERE psT.name = "Thandi"
CREATE
  (psJ:Person { name: "Johan", from: "Pretoria",  hobby: "surfing" }),
  (psN:Person { name: "Neo",   from: "Cape Town", hobby: "soccer"  }),
  (psT)-[:FOLLOWS {since: 2012}]->(psJ),
  (psT)-[:FOLLOWS {since: 2009}]->(psN),
  (psJ)-[:FOLLOWS {since: 2010}]->(psT)

Step-by-step walkthrough:

  1. MATCH … WHERE first finds the existing Thandi node and binds it to psT.
  2. CREATE then creates two new nodes (psJ Johan, psN Neo), each with label Person and 3 properties.
  3. Three relationships are created using the variables:
    • (psT)-[:FOLLOWS {since: 2012}]->(psJ) → Thandi → Johan, since 2012.
    • (psT)-[:FOLLOWS {since: 2009}]->(psN) → Thandi → Neo, since 2009.
    • (psJ)-[:FOLLOWS {since: 2010}]->(psT) → Johan → Thandi, since 2010.
  4. Result (slide screenshot): "Created 2 nodes, created 3 relationships, set 9 properties, added 2 labels." — check the count: 2 nodes × 3 properties = 6, plus 3 relationships × 1 property (since) = 3 → 9 properties.
  5. The variables (psT, psJ, psN) exist only within this one query — they let the relationship patterns refer to the nodes just created.

⚠️ Important warning from the slide

  • CREATE does not check whether the data already exists.
  • Running the same CREATE statement repeatedly can create duplicate nodes/relationships.
  • MERGE can be used when you want "match if it exists, otherwise create."

Example (added for clarity):

MERGE (psN:Person { name: "Neo" })    // finds Neo if present, otherwise creates him

Running this twice leaves one Neo node; running CREATE (:Person {name:"Neo"}) twice leaves two.

7.4.1 MATCH — Everything Connected (from the slides)

MATCH (n)-[r]->(m)
RETURN n, r, m

Step-by-step walkthrough:

  1. (n) → the starting node (no label → any node).
  2. -[r]-> → a relationship, stored in variable r, pointing from n to m.
  3. (m) → the connected node.
  4. RETURN n, r, m → return all three.
  5. Graph mode shows the three-node network; Table mode (slide screenshot) lists one row per relationship:
n r m
Thandi FOLLOWS Johan
Thandi FOLLOWS Neo
Johan FOLLOWS Thandi
  1. Three relationships exist, so three rows are returned (Neo has no outgoing relationship, so Neo appears only in the m column).

7.5 MATCH — Pattern Matching: Whom Does Thandi Follow? (from the slides)

MATCH (psn:Person)-[:FOLLOWS]->(followed)
WHERE psn.name = "Thandi"
RETURN psn, followed

Step-by-step walkthrough:

  1. MATCH describes the pattern from known nodes to found nodes.
  2. (psn:Person) starts the pattern with a Person (qualified by the WHERE clause → Thandi).
  3. -[:FOLLOWS]-> matches only relationships of type FOLLOWS, in the arrow's direction (outgoing from psn).
  4. (followed) is bound to the people Thandi follows.
  5. Result: Thandi paired with Johan and Thandi paired with Neo → two rows.

Variation — return only the followed people (from the slides)

MATCH (psn:Person)-[:FOLLOWS]->(followed)
WHERE psn.name = "Thandi"
RETURN followed
  • Returns just the Johan and Neo nodes; in Graph mode, clicking a node (e.g., Neo or Johan) displays its properties (name, from, hobby).

📌 Extra Examples (added for step-by-step clarity)

// Who follows Thandi?  (reverse the arrow direction)
MATCH (follower)-[:FOLLOWS]->(psT:Person)
WHERE psT.name = "Thandi"
RETURN follower
  • Result: Johan only (Johan → Thandi). Swapping the direction of the arrow changes the question from "whom does she follow?" to "who follows her?"
// Whom does Thandi follow, and since when?
MATCH (psT:Person)-[f:FOLLOWS]->(followed)
WHERE psT.name = "Thandi"
RETURN followed.name, f.since
  • Result: Johan, 2012 and Neo, 2009 — relationship properties are accessed with the same dot notation via the relationship's variable (f.since).

8. Questions & Memo

Section 2 — Graph Theory

Q1: Define a graph formally, and explain how a weighted edge is represented.

A1: A graph is G = (V, E), where V is a set of vertices and E a set of edges; each edge is a tuple (vᵢ, vⱼ) with vᵢ, vⱼ ∈ V. A weighted edge adds a third component w: (vᵢ, vⱼ, w).

Q2: Distinguish between a path and a cycle, and between a directed graph and an undirected one.

A2: A path is a sequence of vertices connected by edges; a cycle (directed graph) is a path that starts and ends at the same vertex with no other repeated vertices. In a directed graph (digraph) all edges are one-way; edges in other graphs may be two-way.

Q3 (Code Tracing): Using the V0–V5 graph (V0→V1:5, V0→V5:2, V1→V2:4, V2→V3:9, V3→V4:7, V3→V5:3, V4→V0:1, V5→V2:1, V5→V4:8), find a cycle containing V0 and give its total weight.

A3: V0 → V5 → V4 → V0, weight 2 + 8 + 1 = 11. (Another: V0 → V1 → V2 → V3 → V4 → V0 = 5 + 4 + 9 + 7 + 1 = 26.)

Q4: What is the weight of the path V0 → V5 → V2 → V3?

A4: 2 + 1 + 9 = 12.

Q5: What is a subgraph?

A5: A graph G′ made of a subset of the vertices and a subset of the edges (connecting those vertices) of G = (V, E).

Section 3 — Graph ADT

Q6: List the operations of the graph ADT and state what addEdge(fromVert, toVert, weight) does.

A6: Graph(), addVertex(vert), addEdge(fromVert, toVert), addEdge(fromVert, toVert, weight), getVertex(vertKey), getVertices(), and in. addEdge(fromVert, toVert, weight) adds a new weighted, directed edge connecting the two vertices.

Section 4 & 5 — Graph Databases and Neo4j

Q7: Name the three simple concepts a graph database uses to store data, and say what each represents in Neo4j.

A7: Nodes (entities / data records), relationships (connections / edges between nodes), properties (named key-value attributes describing nodes and relationships).

Q8: Give three primary uses and three example systems for graph databases.

A8: Uses: social networks, recommendations, forensic investigations. Examples: Neo4j, Amazon Neptune, TigerGraph, ArangoDB.

Q9: State five facts about Neo4j as a DBMS.

A9: Any five of: a GDBMS based on the graph theory model; developed primarily with Java/JVM technologies; stores nodes, relationships and properties; uses Cypher (declarative); provides APIs/drivers; has Community and Enterprise editions; Community is licensed under GPL v3.

Q10: What is a label, and can a node have more than one? Do labels have properties?

A10: A label groups/classifies nodes (e.g., Person). A node can have zero or more labels. Labels have no properties.

Q11: What does it mean that Neo4j has a "flexible schema"?

A11: Different nodes can have different sets of properties, labels classify nodes, and constraints and indexes can be added when data integrity or fast lookup is needed.

Q12: List the five components of a Neo4j relationship.

A12: A start node, an end node, exactly one relationship type, an optional set of properties, and a direction.

Q13: In the Thandi/Neo/Johan graph, why is since stored on the relationship rather than on a node?

A13: Because it describes the connection (when one person began following another), not either person; relationships in a property graph are data records that can hold properties. It also differs per relationship (2009, 2010, 2012), which a node-level property could not express.

Section 6 — Neo4j Desktop

Q14: Match each tool to its purpose: Query, Bloom, Cypher Shell, ETL Tool.

A14: Query — write/run Cypher, view table & graph results. Bloom — visual graph exploration, often without Cypher. Cypher Shell — command-line interface. ETL Tool — import data from relational databases into Neo4j.

Q15: List the steps to connect to a database and run a Cypher query in Neo4j Desktop.

A15: (1) Start Neo4j Desktop; (2) start the local database instance; (3) open Query; (4) authenticate with your Neo4j credentials; (5) enter and execute Cypher queries.

Section 7 — Cypher

Q16: What does it mean that Cypher is declarative?

A16: It describes what result you want (the pattern to find or create), not how the database should find it — like SQL.

Q17 (Code Tracing): Explain each part of CREATE (psT:Person { name: "Thandi", from: "Durban", hobby: "singing"}).

A17: CREATE creates data; ( ) denotes a node; psT is the variable; :Person is the label; { … } holds the three properties (name, from, hobby). Result: 1 node, 3 properties, 1 label created.

Q18 (Code Tracing): Explain MATCH (psT:Person) WHERE psT.name = "Thandi" RETURN psT;

A18: MATCH finds nodes matching the pattern (psT:Person) (any node labelled Person, bound to psT); WHERE keeps only those whose name property equals "Thandi"; RETURN outputs the matching node(s).

Q19 (Code Tracing): The CREATE statement that adds Johan and Neo and three FOLLOWS relationships reports "Created 2 nodes, created 3 relationships, set 9 properties, added 2 labels." Explain where "9 properties" and "2 labels" come from.

A19: Properties: 2 new nodes × 3 properties (name, from, hobby) = 6, plus 3 relationships × 1 property (since) = 3 → 9. Labels: each of the 2 new nodes gets the label Person → 2 (Thandi already existed).

Q20: What problem arises if you run the same CREATE statement twice, and how do you avoid it?

A20: CREATE does not check whether the data already exists, so duplicate nodes/relationships are created. Use MERGE ("match if it exists, otherwise create").

Q21 (Code Tracing): What does MATCH (n)-[r]->(m) RETURN n, r, m return for the Thandi/Johan/Neo graph, in table mode?

A21: Three rows — (Thandi, FOLLOWS, Johan), (Thandi, FOLLOWS, Neo), (Johan, FOLLOWS, Thandi).

Q22 (Code Tracing): What does this return, and how many rows? MATCH (psn:Person)-[:FOLLOWS]->(followed) WHERE psn.name = "Thandi" RETURN followed

A22: The people Thandi follows: Johan and Neo — 2 rows.

Q23: Write a Cypher query that returns the names of the people who follow Thandi.

A23:

MATCH (follower:Person)-[:FOLLOWS]->(t:Person)
WHERE t.name = "Thandi"
RETURN follower.name

(Result: Johan.)

Q24: Write a query that returns the name of everyone Thandi has followed since before 2010, together with the year.

A24:

MATCH (t:Person)-[f:FOLLOWS]->(p:Person)
WHERE t.name = "Thandi" AND f.since < 2010
RETURN p.name, f.since

(Result: Neo, 2009 — Johan (2012) is excluded.)
