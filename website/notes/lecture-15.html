Example (added for clarity)

Lectures 13–21 were about storing and processing big data. This lecture asks: what do we do with it? Data mining is the step that turns stored data into knowledge — e.g., "customers who buy bread and cookies also buy coffee", "this transaction looks fraudulent", "these customers behave alike."

2. Data Mining — Definition

  • Data mining is the process of analysing large datasets to discover useful patterns, relationships, trends and predictive models.
  • It uses techniques from statistics, machine learning, database systems and pattern recognition to extract knowledge that supports decision-making.
  • Examples (from the slides):
    • Identifying products frequently purchased together.
    • Predicting whether a transaction is fraudulent.
    • Grouping customers by similar purchasing behaviour.
    • Forecasting future demand from historical data.

2.1 Data Mining vs Data Warehousing

Aspect Data warehousing Data mining
Primary purpose Integrate and organise data for reporting and analysis Discover patterns and build predictive or descriptive models
Typical activities Data integration, storage, querying, reporting Association rule mining, classification, clustering, regression
Main output Curated datasets, reports, analytical views Patterns, rules, clusters, predictive models
Relationship Provides a source of historical, integrated data Can analyse data in a warehouse or other sources

Important (slide): a data warehouse is NOT a prerequisite for data mining — it can be done on operational databases, data lakes and other datasets, provided the data can be accessed and prepared appropriately.

2.2 Knowledge Discovery in Databases (KDD)

  • KDD is the broader, iterative process of extracting useful and understandable knowledge from data. Data mining is one stage of KDD.
Stage Description
1. Data selection Identify relevant data sources and attributes
2. Data cleansing Handle missing, inconsistent, duplicated or incorrect data
3. Data enrichment Integrate additional data or relevant background knowledge
4. Data transformation Convert data into a suitable representation for analysis
5. Data mining Apply algorithms to identify patterns or construct models
6. Evaluation & presentation Assess validity and usefulness of results and communicate findings
  • The workflow may return to earlier stages when data-quality problems, unsuitable models or unexpected results appear (it is iterative).

Worked Example (added) — KDD for a supermarket

  1. Select: till transactions and loyalty-card data for 2025.
  2. Cleanse: remove duplicate scans, fix missing product codes.
  3. Enrich: add product category and store region.
  4. Transform: turn each receipt into a basket (set of items).
  5. Mine: run association-rule mining on the baskets.
  6. Evaluate/present: show managers the strong, useful rules; discard trivial ones; go back to step 2 if results look odd (e.g., a "product" that is actually a bag charge).

2.3 Goals of Data Mining — PICO

Goal Meaning Example (from the slides)
P — Prediction Estimate an unknown or future outcome from observed data Predicting next month's electricity demand
I — Identification Detect the presence of a particular item, event or activity Identifying potentially fraudulent transactions
C — Classification Assign records to predefined categories Classifying an email as spam or legitimate

Important distinction (slide): PICO are goals/objectives. Classification, regression and clustering are analytical techniques used to achieve them. (Note that "classification" appears in both lists — as a goal (assign to categories) and as a technique (Section 5).)

3. Association Rules

  • Frequently used to generate rules from market-basket data.
    • A market basket = the set of items a consumer purchases during one visit to a supermarket.
  • The set of items purchased is an itemset.
  • An association rule has the form X ⇒ Y, where X = {x₁,…,xₙ} and Y = {y₁,…,yₘ} are sets of items (all items distinct).
  • To be of interest, a rule must satisfy a minimum support and minimum confidence.

3.1 Support and Confidence

Measure Definition Formula
Support The percentage of transactions that contain all the items in the rule (LHS ∪ RHS) support(X ⇒ Y) = support(X ∪ Y)
Confidence For a rule A ⇒ B, the conditional probability that B is true when A is known to be true confidence = support(LHS ∪ RHS) / support(LHS)

3.2 Worked Example — Slide: milk ⇒ juice and bread ⇒ juice

Transaction table (slide figure):

Transaction_id Time Items_bought
101 6:35 milk, bread, cookies, juice
792 7:38 milk, juice
1130 8:05 milk, eggs
1735 8:40 bread, cookies, coffee

Step-by-step calculation:

  1. Rule milk ⇒ juice:
    • Transactions with milk: 101, 792, 1130 → 3.
    • Transactions with milk AND juice: 101, 792 → 2.
    • Support = 2/4 = 50%. Confidence = 2/3 = 66.7%.
  2. Rule bread ⇒ juice:
    • Transactions with bread: 101, 1735 → 2.
    • Transactions with bread AND juice: 101 → 1.
    • Support = 1/4 = 25%. Confidence = 1/2 = 50%.
  3. Goal of mining association rules (slide): generate rules that exceed user-specified support and confidence thresholds.
  4. Interpretation: "milk ⇒ juice" holds in half of all transactions, and two-thirds of milk buyers also bought juice.

Remember: support uses the whole database as denominator (4 transactions); confidence uses only the transactions containing the left-hand side. Confidence is not symmetric: juice ⇒ milk has confidence 2/2 = 100%, while milk ⇒ juice is 66.7%.

3.3 Generating Association Rules — the Two-Step Process

  1. Generate all itemsets whose support exceeds the threshold — called large (frequent) itemsets.
  2. Generate rules from each frequent itemset: for itemset X and a subset Y of X, let Z = X − Y. If support(X) / support(Z) > minimum confidence, then the rule Z ⇒ Y is valid.

Example (added): X = {milk, juice}, Y = {juice}, Z = {milk} → confidence of milk ⇒ juice = support({milk, juice}) / support({milk}) = 50% / 75% = 66.7%.

3.4 Reducing Search Complexity — Two Properties

Property Statement
Downward closure A subset of a large (frequent) itemset must also be large.
Anti-monotonicity A superset of a small (infrequent) itemset is also small — it lacks sufficient support, so it need not be considered.

Example (added): if {bread, juice} is infrequent, then {bread, juice, milk} cannot be frequent — it is pruned without counting.

4. Algorithms for Finding Frequent Itemsets

4.1 The Apriori Algorithm (Agrawal & Srikant, 1994)

  • Uses downward closure of support to find frequent itemsets efficiently:
    • If an itemset is frequent, all its non-empty subsets are frequent.
    • If an itemset is infrequent, none of its supersets can be frequent.
  • Generates candidate itemsets iteratively, starting with single items and extending to larger itemsets, pruning candidates that cannot satisfy minimum support.

Algorithm 28.1 (summary):

  • Input: database D of m transactions; minimum support mins (a fraction of m). Output: frequent itemsets L₁, L₂, …, L_k.
  1. Scan once and compute support(i_j) = count(i_j) / m for each single item.
  2. C₁ (candidate 1-itemsets) = all items.
  3. L₁ = items in C₁ with support ≥ mins.
  4. Repeat (k = 1, 2, …):
    1. L_{k+1} = ∅.
    2. Create C_{k+1} by combining members of L_k that have k−1 items in common (extending frequent k-itemsets by one item).
    3. Keep only candidates whose every size-k subset is in L_k (downward-closure pruning).
    4. Scan the database once to compute the support of each candidate; those with support ≥ mins go into L_{k+1}.
    5. If L_{k+1} is empty → stop; else k = k + 1.

Worked Example (added for step-by-step clarity) — Apriori on the slide's four transactions, mins = 50% (≥ 2 transactions)

Pass 1 — single items (m = 4):

Item Count Support Frequent?
milk 3 75% Yes
bread 2 50% Yes
cookies 2 50% Yes
juice 2 50% Yes
eggs 1 25% No
coffee 1 25% No

→ L₁ = {milk}, {bread}, {cookies}, {juice}. (eggs and coffee are dropped — and no itemset containing them will ever be considered.)

Pass 2 — candidate pairs (C₂ = all pairs from L₁):

Pair Transactions Count Support Frequent?
{milk, bread} 101 1 25% No
{milk, cookies} 101 1 25% No
{milk, juice} 101, 792 2 50% Yes
{bread, cookies} 101, 1735 2 50% Yes
{bread, juice} 101 1 25% No
{cookies, juice} 101 1 25% No

→ L₂ = {milk, juice}, {bread, cookies}.

Pass 3 — candidate triples: members of L₂ must share k−1 = 1 item to be combined; {milk, juice} and {bread, cookies} share none → C₃ = ∅ → L₃ is empty → terminate.

Result: frequent itemsets are L₁ ∪ L₂.

Generating rules (minimum confidence 70%):

Rule Confidence Valid?
milk ⇒ juice support{milk,juice}/support{milk} = 50/75 = 66.7% No
juice ⇒ milk 50/50 = 100% Yes
bread ⇒ cookies 50/50 = 100% Yes
cookies ⇒ bread 50/50 = 100% Yes

4.2 The Sampling Algorithm

  • Selects samples of the transaction database that individually fit into memory; frequent itemsets are found for each sample.
  • If those frequent itemsets form a superset of the frequent itemsets for the entire database, the real frequent itemsets can be obtained by scanning the remainder of the database.
  • Negative border (w.r.t. a set of frequent itemsets S and item set I): the minimal itemsets in PowerSet(I) that are not in S — i.e., the closest itemsets that could also be frequent.
    • If a set X is not in the frequent itemsets but all its subsets are, then X is in the negative border.
    • If an itemset in the negative border turns out to be frequent, a superset of it might also be frequent → a second pass over the database is needed to be sure all frequent itemsets are found.

Example (added): if frequent itemsets from a sample are {a}, {b}, {c}, {a,b}: then {a,c} and {b,c} are in the negative border (not frequent, but their subsets {a},{b},{c} all are) — they are the "next candidates" to double-check against the full database.

4.3 The Frequent-Pattern (FP) Tree Algorithm

  • Reduces the number of candidate itemsets by producing a compressed version of the database as an FP-tree, which stores relevant information and allows efficient discovery of frequent itemsets.
  • Two steps: (1) build the FP-tree; (2) use the tree to find frequent itemsets (FP-growth).

Step 1 — Building the FP-tree:

  1. Compute frequent 1-itemsets with counts; sort them in non-increasing order of count.
  2. Create the root labelled "null."
  3. For each transaction T, list its frequent items in that sorted order; call the first item the head and the rest the tail.
  4. Insert recursively: if the current node has a child with the head's item name, increment its count; else create a new node with count 1 (linked to its parent and to the item header table). If the tail is non-empty, repeat using the tail (new head = first item of tail).

Step 2 — FP-growth (Algorithm 28.2, summary):

  • If the tree is a single path: for each combination β of the path's nodes, generate pattern (β ∪ α) with support = minimum support of nodes in β.
  • Otherwise: for each item i in the tree's header: generate pattern β = (i ∪ α) with support = i.support; build β's conditional pattern base and conditional FP-tree; if non-empty, recursively call FP-growth(β_tree, β).

Worked Example (added) — Building the FP-tree for the slide's data, min support = 2

  1. Frequent items (sorted by count): milk (3), then bread (2), cookies (2), juice (2) (ties may be ordered arbitrarily but consistently).
  2. Each transaction with frequent items in that order:
    • 101 → milk, bread, cookies, juice
    • 792 → milk, juice
    • 1130 → milk (eggs dropped)
    • 1735 → bread, cookies (coffee dropped)
  3. Insert into the tree:
null
├── milk (3)
│   ├── bread (1) ── cookies (1) ── juice (1)     ← from 101
│   └── juice (1)                                  ← from 792
└── bread (1) ── cookies (1)                       ← from 1735
  1. Why it's compact: the shared prefix milk is stored once with count 3 — transactions with common starts are merged. FP-growth then mines this tree without generating and counting many candidate itemsets.

4.4 The Partition Algorithm

  1. Divide the transaction database into non-overlapping partitions.
  2. Find the locally frequent itemsets in each partition (using the minimum-support threshold applied consistently to the global requirement).
  3. Union of the locally frequent itemsets = the global candidate set.
  4. Scan the full database to compute the global support of these candidates.
  5. Keep only candidates meeting the global minimum support.
  • Key property: an itemset that is globally frequent must be frequent in at least one partition (with an appropriate local threshold). The second scan decides which candidates are globally frequent.

4.5 Comparison of the Four Algorithms (added)

Algorithm Main idea Database scans Notes
Apriori Level-wise candidate generation with downward-closure pruning One per level (k passes) Simple; many candidates for large data
Sampling Mine in-memory samples, then verify using the negative border 1–2 (second pass if a negative-border itemset is frequent) Fast but needs a verification pass
FP-tree / FP-growth Compress DB into a tree; no candidate generation 2 (count items, then build tree) Efficient with many frequent patterns
Partition Mine each partition locally, union, then verify globally 2 Suits large/distributed data

5. Association Rules Among Hierarchies, Multi-dimensional and Negative Rules

5.1 Hierarchies (Taxonomies)

  • Associations can occur among hierarchies of items — items in a supermarket/department store/sports shop are categorised into classes and subclasses.
  • Slide figure 28.3 — supermarket taxonomy:
    • Beverages: Carbonated (colas, clear drinks, mixed drinks) and Noncarbonated (bottled juices [orange, apple, others], bottled water [plain, clear], wine coolers).
    • Desserts: Ice cream (e.g., rich cream), Baked, Frozen yogurt (reduce, healthy).
  • Key point: the whole groups may not yield a rule like beverages ⇒ desserts, but specific, lower-level associations may have enough support and confidence — e.g., healthy-brand frozen yogurt ⇒ bottled water, or rich cream-brand ice cream ⇒ wine cooler.

5.2 Multi-dimensional Association Rules

  • Single-dimension example: Items_bought(milk) ⇒ Items_bought(juice).
  • Multidimensional rules involve several attributes (dimensions), e.g., Time(6:30…8:00) ⇒ Items_bought(milk).
  • Dimensions are attributes of records (columns of a relation) and can be categorical or quantitative.
  • Handling quantitative attributes: partition values into non-overlapping intervals, e.g., salary:
    • 0 < salary < 29,999 ⇒ {Kia, Hyundai}
    • 30,000 < salary < 99,999 ⇒ {Honda, Toyota}
    • 100,000 < salary < 149,000 ⇒ {Lexus, Mercedes}
    • 150,000 < salary < 300,000 ⇒ {Porsche, BMW}

Using the slide's transactions (added): the rule Time(6:30–8:00) ⇒ Items_bought(milk) — transactions at 6:35 (101) and 7:38 (792) are in the time range and both contain milk → confidence 100%, support 2/4 = 50%.

5.3 Negative Association Rules

  • Rules such as: those who buy soft drink "Wakeup" are not likely to buy chips "Nightos".
  • Very difficult to discover because the support is very low by definition. (Reference on the slide: Savasere, Omiecinski & Navathe, 1998.)

5.4 Complications with Association Rules

  1. The cardinality of itemsets is usually extremely large.
  2. Mining is harder when transactions vary by location and season.
  3. Item classifications exist along multiple dimensions that must be taken into account.
  4. Data quality is variable — missing, erroneous, conflicting and redundant data.

6. Classification

  • Classification = learning a model that describes different classes of data.
  • Supervised learning: the classes are predetermined.
  • Learning uses a training set of pre-classified data.
  • The model is usually a decision tree or a set of rules.

6.1 Decision Tree Induction (Algorithm 28.3)

  • Input: training records R₁…R_m and attributes A₁…A_n. Output: a decision tree.

Build_tree(records, attributes):

  1. Create a node N.
  2. If all records belong to the same class C → return N as a leaf labelled C.
  3. If attributes is empty → return N as a leaf labelled with the majority class.
  4. Select the attribute A_i with the highest information gain; label N with A_i.
  5. For each known value v_j of A_i:
    • Add a branch for the condition A_i = v_j; S_j = records where A_i = v_j.
    • If S_j is empty → add a leaf with the majority class (of the parent's records).
    • Else → add the node returned by Build_tree(S_j, attributes − A_i).
  • Information gain (concept): how much choosing an attribute reduces uncertainty about the class — the attribute that best separates the classes is chosen first (so it appears nearest the root).

6.2 Worked Example — Slide Figure 28.7 (decision tree)

Tree structure:

Salary
├── < 20K        → class "no"   {records 4, 5}
├── 20K … 50K    → Age
│                    ├── < 25   → class "no"   {record 3}
│                    └── >= 25  → class "yes"  {record 6}
└── >= 50K       → class "yes"  {records 1, 2}
  • Leaf nodes are represented by the sets of record IDs (RIDs) of the partitioned records.

Extracting rules (slide):

  • Rule 1: IF 50K > salary ≥ 20K AND age ≥ 25 THEN class is "yes".
  • Rule 2: IF 50K > salary ≥ 20K AND age < 25 THEN class is "no".

Step-by-step:

  1. Each path from root to a leaf = one rule (conditions along the path are joined with AND).
  2. The root tests Salary (chosen as best attribute); only the middle salary band needs a second test on Age.
  3. Using the tree (added): a new customer with salary 35K and age 30 → Salary branch 20K–50K → Age ≥ 25 → class "yes". A customer with salary 15K → "no" (age not even needed).
  4. All five rules in full: salary < 20K → no; 20K ≤ salary < 50K & age < 25 → no; 20K ≤ salary < 50K & age ≥ 25 → yes; salary ≥ 50K → yes.

7. Clustering

  • Clustering is an unsupervised learning technique that groups records by similarity of attributes, without predefined class labels.
  • Objective: groups whose records are relatively similar under a chosen distance or similarity measure.
  • Examples: grouping customers by purchasing behaviour; grouping network devices by traffic patterns; identifying unusual groups/anomalies in security logs.
  • Unlike classification, clustering does not require a predefined target class for every training record.

7.1 Classification vs Clustering (added)

Aspect Classification Clustering
Learning type Supervised Unsupervised
Class labels Predefined (training set pre-classified) None — groups are discovered
Output Decision tree / rules Groups (clusters) + centroids
Example Spam vs legitimate Customer segments

7.2 K-Means Clustering

  • Input: dataset D with m records and a specified number of clusters k. Output: k clusters and their centroids.
  1. Initialise k centroids (using a method such as k-means++).
  2. Assign each record to the cluster with the nearest centroid (chosen distance measure).
  3. Recalculate each centroid as the mean of the records assigned to it.
  4. Repeat steps 2–3 until convergence or another stopping condition.
  • Objective: minimise the within-cluster sum of squared distances to the centroids.
  • Results depend on: the initialisation, the choice of k, feature scaling and outliers.
  • Limitation: standard k-means suits numerical data and can perform poorly when clusters have very different sizes, densities or non-spherical shapes.

Worked Example (added) — k = 2 on the values 1, 2, 10, 11

  1. Initialise centroids: c₁ = 1, c₂ = 10.
  2. Assign: 1 → c₁ (distance 0); 2 → c₁ (1 vs 8); 10 → c₂; 11 → c₂. Clusters: {1, 2} and {10, 11}.
  3. Update centroids: c₁ = (1+2)/2 = 1.5; c₂ = (10+11)/2 = 10.5.
  4. Reassign: nothing changes → converged. Final clusters {1, 2} and {10, 11}.

8. Additional Data Mining Approaches

8.1 Sequential Pattern Analysis

  • Looks for sequences of itemsets. Transactions ordered by time form a sequence of itemsets.
  • Support for a sequence S = the percentage of the given sequences U of which S is a subsequence.
  • A sequence S₁, S₂, S₃, … predicts that a customer who buys itemset S₁ is likely to buy S₂ and then S₃, and so on.

Example (added): customers who buy a phone, then a phone case, then a screen protector within a month — the ordered sequence is the pattern.

8.2 Time Series Analysis

  • A time series = a sequence of observations recorded over time, often at regular intervals.
  • Examples: daily stock prices, hourly electricity consumption, network traffic per minute, monthly sales revenue.
  • Used to identify trends, seasonality, unusual observations, temporal relationships, and to forecast future values.
  • Difference from sequential pattern mining (slide): time-series analysis often examines numerical observations and their temporal structure; sequential pattern mining commonly finds recurring ordered sequences of events/itemsets. They can overlap.

8.3 Regression

  • Regression is a special application of the classification rule: a classification rule viewed as a function over variables that maps them to a target class variable is called a regression rule.
  • A regression equation estimates a dependent variable using a set of independent variables and constants.
  • Slide example: relation LAB_TESTS(patient ID, test 1, test 2, …, test n); the target is P = probability of survival. Rule form: (test 1 in range₁) AND (test 2 in range₂) AND … AND (test n in range_n) ⇒ P = x, or x < P ≤ y, i.e., P = f(test 1, …, test n).
  • If Y = f(x₁, …, x_n) and f is linear in the variables xᵢ, deriving f from given tuples ⟨x₁,…,x_n, y⟩ is linear regression — a common statistical technique for fitting observations in n dimensions to the target y.

Example (added): predicting house price y = 50,000 + 12,000 × bedrooms + 800 × floorArea — a linear function of the inputs; regression finds the constants from past sales.

8.4 Neural Networks

  • Machine learning models made of interconnected computational units arranged in layers; connections have learned weights adjusted during training.
  • Supervised learning: learn from examples with known target outputs. Unsupervised / self-supervised: learn representations/patterns with other training objectives.
  • Applications: image recognition, text processing, anomaly detection, forecasting, classification.
  • Strengths/weaknesses: can model complex relationships, but may need substantial training data and computing resources, and decisions can be difficult to interpret.
  • Time series: can be processed using suitable architectures — recurrent networks, temporal convolutional networks, Transformers.

8.5 Genetic Algorithms (GAs)

  • A class of randomised search procedures capable of adaptive and robust search over a wide range of search-space topologies; modelled on biological evolution.
  • How they work:
    1. Initialise a population of candidate solutions.
    2. Evaluate each with a fitness function (defines which solutions survive).
    3. Select candidates for reproduction.
    4. Apply crossover to combine candidate solutions.
    5. Apply mutation to introduce variation.
    6. Form a new population and repeat until a stopping condition is met.
  • Example (slide): a delivery company searches for vehicle routes that reduce total travel distance while respecting delivery time windows and vehicle-capacity constraints (this links to the Optimisation goal in PICO).
  • Caveat: GAs are heuristic — they can find good solutions to complex optimisation problems but do not guarantee the global optimum.

10. Data Mining Tools and the Future

10.1 Techniques Used in Commercial Tools

  • Common: association rules, clustering, neural networks, sequencing, statistical analysis; also decision trees (a representation of classification/clustering rules) and statistical analyses (various regressions, etc.).
  • Some products add advanced techniques: genetic algorithms, case-based reasoning, Bayesian networks, nonlinear regression, combinatorial optimisation, pattern matching, fuzzy logic.

10.2 Representative Tools (from the slides)

Tool/environment Use
Python: pandas, scikit-learn Data preparation and machine learning
R Statistical analysis and data visualisation
Apache Spark MLlib Distributed machine learning for large datasets
Database/cloud platforms: BigQuery ML, other managed services Model development close to stored data
Visual analytics: KNIME and commercial environments Workflow-based data preparation and modelling
  • Tool selection depends on dataset size, computing resources, analytical requirements, cost, explainability and integration with existing systems.

10.3 Future of Data Mining

  • Tools keep evolving, incorporating algorithms from AI, machine learning, statistics and optimisation.
  • Primary direction: analysing terabytes and petabytes in Big Data systems (Chapter 25 / Lectures 21).
  • Big-data systems get their own mining libraries — e.g., Mahout on top of Hadoop, and Spark MLlib.
  • Data mining will be tied to data housed in the cloud in data warehouses and brought in as needed using OLAP (Online Analytical Processing) servers.
  • Business Analytics is the primary goal of the currently advancing Spark technology.

11. Questions & Memo

Section 2 — Data Mining, KDD, PICO

Q1: Define data mining and give two examples.

A1: Analysing large datasets to discover useful patterns, relationships, trends and predictive models (using statistics, ML, database systems, pattern recognition) to support decisions. Examples: finding products frequently bought together; predicting fraudulent transactions; grouping customers; forecasting demand.

Q2: Is a data warehouse required for data mining? Contrast the two.

A2: No — mining can use operational databases, data lakes and other datasets (given access/preparation). A warehouse integrates and organises data for reporting (output: curated datasets/reports); mining discovers patterns and builds models (output: patterns, rules, clusters, predictive models).

Q3: List the stages of KDD and state how KDD relates to data mining.

A3: Data selection → cleansing → enrichment → transformation → data mining → evaluation & presentation. KDD is the broader, iterative process; data mining is one stage of it.

Q4: What does PICO stand for? Match each with an example.

A4: Prediction (next month's electricity demand), Identification (potentially fraudulent transactions), Classification (spam vs legitimate email), Optimisation (allocating delivery vehicles to minimise travel time).

Q5: Why are classification, regression and clustering not "goals" in the PICO sense?

A5: They are analytical techniques used to achieve goals; PICO lists the objectives.

Section 3 & 4 — Association Rules

Q6: Define support and confidence and give the confidence formula.

A6: Support = percentage of transactions containing all items of the rule (LHS ∪ RHS). Confidence = conditional probability of RHS given LHS = support(LHS ∪ RHS) / support(LHS).

Q7 (Calculation): Using the four slide transactions (101: milk, bread, cookies, juice; 792: milk, juice; 1130: milk, eggs; 1735: bread, cookies, coffee), calculate support and confidence of milk ⇒ juice and bread ⇒ juice.

A7: milk ⇒ juice: support 2/4 = 50%, confidence 2/3 = 66.7%. bread ⇒ juice: support 1/4 = 25%, confidence 1/2 = 50%.

Q8 (Calculation): For the same data, what is the confidence of cookies ⇒ bread, and of juice ⇒ milk?

A8: cookies ⇒ bread: cookies in 101 and 1735 (2); both also have bread → 2/2 = 100%. juice ⇒ milk: juice in 101, 792 (2); both have milk → 100%.

Q9: Describe the two-step process for generating association rules.

A9: (1) Find all frequent (large) itemsets with support above the threshold. (2) For each frequent itemset X and subset Y, with Z = X − Y, Z ⇒ Y is valid if support(X)/support(Z) exceeds the minimum confidence.

Q10: Explain downward closure and anti-monotonicity and how they help.

A10: Downward closure: every subset of a frequent itemset is frequent. Anti-monotonicity: every superset of an infrequent itemset is infrequent. Together they allow pruning of candidates without counting them, reducing the search space.

Q11 (Code/Algorithm Tracing): Run Apriori with minimum support 50% on the four transactions above. What are L₁ and L₂, and why does the algorithm stop?

A11: L₁ = {milk, bread, cookies, juice} (eggs, coffee have 25%). L₂ = {milk, juice}, {bread, cookies} (each 50%). No two members of L₂ share one item, so C₃ is empty → L₃ empty → stop.

Q12: Describe how Apriori generates C_{k+1} from L_k.

A12: Combine members of L_k that have k−1 items in common, then keep only candidates whose every k-size subset is in L_k; then scan the database to count their support and keep those ≥ minimum support.

Q13: Explain the sampling algorithm and the negative border.

A13: Mine in-memory samples for frequent itemsets; if these form a superset of the true frequent itemsets, scan the rest of the database to get the real ones. The negative border is the set of minimal itemsets not in the frequent set but all of whose subsets are — the closest candidates that could also be frequent; if one of them proves frequent, a second pass is needed.

Q14: How does the FP-tree algorithm reduce candidate generation?

A14: It compresses the database into an FP-tree (frequent items sorted by decreasing count; transactions sharing prefixes share nodes with counts), then FP-growth mines frequent patterns from the tree using conditional pattern bases/conditional FP-trees — without generating large numbers of candidate itemsets.

Q15 (Tracing): Build the FP-tree for transactions {milk, bread, cookies, juice}, {milk, juice}, {milk}, {bread, cookies} (minimum support 2; order milk, bread, cookies, juice). Give the counts at the root's children.

A15: Root → milk (3) and root → bread (1). Under milk: bread (1) → cookies (1) → juice (1) and juice (1). Under the root's bread: cookies (1).

Q16: Describe the partition algorithm and its key property.

A16: Split the DB into non-overlapping partitions, find locally frequent itemsets in each, union them into global candidates, scan the full DB to get global support and retain those meeting the global threshold. Key property: a globally frequent itemset must be frequent in at least one partition.

Q17: Why might "beverages ⇒ desserts" fail while "healthy-brand frozen yogurt ⇒ bottled water" succeeds?

A17: The broad groups are too general to show strong association; specific lower-level items in the taxonomy can show enough support and confidence to be valid rules.

Q18: What is a multidimensional association rule? Give an example, and explain how quantitative attributes are handled.

A18: A rule involving several attributes (dimensions), e.g., Time(6:30…8:00) ⇒ Items_bought(milk). Quantitative attributes are partitioned into non-overlapping intervals (e.g., salary bands ⇒ car brands).

Q19: Why are negative association rules hard to discover?

A19: They describe items unlikely to be bought together, so their support is very low by definition.

Q20: List four complications of association rule mining.

A20: Extremely large itemset cardinality; variability by location/season; multi-dimensional item classifications; poor data quality (missing, erroneous, conflicting, redundant).

Section 6 — Classification

Q21: Explain why classification is "supervised" and what a decision tree represents.

A21: The classes are predetermined and the model is learned from a pre-classified training set. A decision tree partitions records by attribute tests, each root-to-leaf path forming a classification rule.

Q22 (Tracing): Using the Figure 28.7 tree (Salary < 20K → no; 20K–50K → Age: < 25 → no, ≥ 25 → yes; ≥ 50K → yes), classify (a) salary 30K, age 22; (b) salary 30K, age 40; (c) salary 60K, age 20.

A22: (a) 20K–50K, age < 25 → "no." (b) 20K–50K, age ≥ 25 → "yes." (c) salary ≥ 50K → "yes."

Q23: In Build_tree, how is the splitting attribute chosen and when is a leaf created?

A23: The attribute with the highest information gain is chosen. A leaf is created when all records belong to the same class, when no attributes remain (majority class), or when a branch's subset is empty (majority class of the parent's records).

Section 7 — Clustering

Q24: Distinguish classification from clustering.

A24: Classification is supervised (predefined classes, training set with labels) and produces trees/rules; clustering is unsupervised (no labels) and groups similar records by a distance/similarity measure.

Q25 (Tracing): Apply k-means (k = 2, initial centroids 1 and 10) to the values 1, 2, 10, 11. Give the final clusters and centroids.

A25: Assign: {1, 2} → centroid 1; {10, 11} → centroid 10. Recalculate: 1.5 and 10.5. Reassigning changes nothing → converged: {1, 2} (centroid 1.5) and {10, 11} (centroid 10.5).

Q26: State three factors that affect k-means results and one limitation.

A26: Initialisation, choice of k, feature scaling, outliers. Limitation: suited to numerical data; poor with clusters of very different sizes, densities or non-spherical shapes.

Section 8 — Other Techniques

Q27: Distinguish sequential pattern mining from time-series analysis.

A27: Sequential pattern mining finds recurring ordered sequences of events/itemsets (e.g., phone → case → screen protector); time-series analysis examines numerical observations over time for trends, seasonality, anomalies and forecasting. They can overlap.

Q28: What is regression and when is it "linear regression"?

A28: A regression function estimates a dependent variable from independent variables and constants (a special application of the classification rule, mapping variables to a numeric target). It is linear regression when the function f is linear in the variables x_i, e.g., y = a + b₁x₁ + b₂x₂.

Q29: State two strengths and two weaknesses of neural networks.

A29: Strengths: model complex relationships; applicable to images, text, anomaly detection, forecasting, classification. Weaknesses: need substantial data and compute; decisions are hard to interpret.

Q30: Describe the steps of a genetic algorithm and its main limitation.

A30: Initialise a population; evaluate with a fitness function; select candidates; apply crossover and mutation; form a new population; repeat until a stopping condition. Limitation: it is heuristic — no guarantee of the global optimum.

Q31 (Scenario): For each task choose a technique: (a) group customers into segments; (b) decide whether a loan applicant is a good or bad risk using past labelled cases; (c) find which products are bought together; (d) minimise delivery distance under time windows; (e) forecast hourly electricity demand.

A31: (a) Clustering (e.g., k-means). (b) Classification (decision tree). (c) Association rules (Apriori/FP-growth). (d) Genetic algorithm (optimisation). (e) Time-series analysis (or regression/neural networks).

Q32: Name four tools/environments for data mining and one factor in choosing among them.

A32: Python (pandas, scikit-learn), R, Spark MLlib, BigQuery ML, KNIME. Factors: dataset size, computing resources, analytical requirements, cost, explainability, integration with existing systems.

Q33: How does data mining relate to the big-data technologies of Lecture 21?

A33: Mining increasingly targets terabytes/petabytes held in big-data systems; those systems provide their own libraries (Mahout on Hadoop, Spark MLlib); and mining uses cloud data warehouses via OLAP servers. Business analytics is the primary goal of Spark.
