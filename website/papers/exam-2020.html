Question 2Big Data / NoSQLPDF p.1 ↗

Why are NoSQL databases suitable for the storage of Big Data?

Show answer Study answer
  • Scalability (volume): NoSQL systems scale out horizontally across many commodity servers by partitioning (sharding) data, instead of scaling one big machine up.
  • Flexible data models (variety): they store key-value, document, wide-column or graph data without a rigid schema, so semi-structured and unstructured data fit naturally.
  • Performance and availability (velocity): data is replicated and distributed for fast reads and writes and for fault tolerance.
  • Relaxed consistency: many give up strict ACID for eventual consistency (BASE) to stay available at scale (the CAP trade-off).
  • They fit parallel processing frameworks such as MapReduce.
Question 3XML storagePDF p.1 ↗

One option for storing XML document data in a database is to store the XML document as a value of one row and one column of a table/relation. a. Give a concise description of this approach. b. Discuss the strengths and weaknesses of this approach.

Show answer Memo

(a) Store the whole XML document as the value of one column in one row (often in an XML type column).

(b) Strengths: easy and fast to insert and retrieve the whole document intact; the hierarchy and order are preserved; no mapping is needed; good when documents are mostly read or archived whole. Weaknesses: searching inside the document means parsing it (for example with xpath()) on every query; internal fields cannot be indexed or constrained like ordinary columns; a small change means rewriting the whole document.

Question 21NoSQL modelsPDF p.6 ↗

Explain the similarities and differences between the data models for NoSQL databases which are classified as key-value stores and NoSQL databases which are classified as wide-column stores.

Show answer Study answer

Similarities: both are NoSQL stores that scale out over clusters, replicate data, are schema-flexible and access data by key; wide-column is effectively an extension of the key-value idea.

Differences: in a key-value store each key maps to a single, opaque value, so you can only get, put or delete by key. In a wide-column store each row key maps to many named columns grouped into column families; rows can have different, sparse sets of columns, so you can read particular columns or column ranges and the structure is richer (for example Cassandra and HBase).

Question 31XML storagePDF p.8 ↗

Another option for storing XML document data in a database is to store the XML document in a shredded form.

  • a. Give a concise description of this approach.
  • b. Discuss the strengths and weaknesses of this approach.
Show answer Memo

Description: shredding decomposes the XML tree into relational tables, with elements and attributes mapped to columns (often one row per repeated element).

Strengths: ordinary SQL, indexes and constraints work on individual values, it joins with other relational data, and partial queries and updates are efficient. Weaknesses: a mapping and schema must be designed first; document order, comments and exact formatting are lost unless extra metadata is stored; reassembling a whole document needs joins; irregular or changing structures are hard to map.

Question 34MongoDBPDF p.9 ↗

The list below gives two of the limitations associated with relational database systems

(i) Due to normalisation, information is obtained from the database through performing expensive joins of 2 or more tables.

(ii) Schema changes are difficult. Database schema changes require program changes. Explain how the MongoDB NoSQL database avoids the above weaknesses.

Show answer Study answer

(i) Joins: MongoDB stores related data embedded in one document (nested documents and arrays), so related information is read in a single lookup with no join. It does not need normalisation across tables.

(ii) Schema changes: documents in a collection need not share a fixed schema. Fields can be added or changed per document without altering a central definition or migrating existing data, so application code is not forced to change.

Question 37NewSQLPDF p.10 ↗

Three of the supporting technologies for the New SQL database management approach are: 1. column-oriented data storage 2. in-memory processing 3. massively parallel processing

Provide a brief explanation of how each of the above technologies supports the New SQL database management approach.

Show answer Study answer
  • Column-oriented storage: values of a column are stored together, so analytic queries read only the columns they need and compress well, which speeds up scans and aggregations.
  • In-memory processing: data is held in RAM, removing the disk I/O bottleneck and giving very low-latency, high-throughput transactions.
  • Massively parallel processing: queries are split into tasks that run in parallel on many nodes (shared-nothing), so the system scales out while keeping SQL and ACID transactions.
Question 38Data miningPDF p.11 ↗
  • a. Give a definition of data mining.
  • b. Briefly describe the phases of the Cross- Industry Standard Process for Data Mining (CRISP-DM) for data mining projects. Explain why each phase is important.
Show answer Study answer

(a) Data mining is the process of analysing large datasets to discover useful patterns, relationships, trends and predictive models that support decision-making (one stage of the wider KDD process).

(b) CRISP-DM phases:

  1. Business understanding: define the goals and success criteria, so the work solves a real problem.
  2. Data understanding: collect and explore the data to judge its quality and relevance.
  3. Data preparation: select, clean, integrate and transform the data into a form the algorithms can use (usually the most time-consuming phase).
  4. Modelling: choose and apply mining techniques and tune their parameters.
  5. Evaluation: check the model meets the business objectives before using it.
  6. Deployment: put the results to use (reports, scoring, integration) and plan monitoring and maintenance.
