Question 13 marksNeo4jPDF p.1 ↗

The following CYPHER query has been executed on a Neo4j database:

   CREATE
     ( psN:Person { name: "Nandi", from: "Joburg" } ),
     ( psJ:Person { name: "Jaco", from: "Pretoria"} ),
     ( cb1:Club { name: "Sundowns"} ),

( cb2:Club { name: "Chiefs"} ),

     ( psN)-[:KNOWS { since: 2014 } ]->(psJ ),
     ( psN)-[:SUPPORTS { since: 2015 } ]->(cb1 ),
     ( psJ)-[:SUPPORTS { since: 2014 } ]->(cb2 );

Which one of the following CYPHER queries will display the names of the ‘Persons’ who support the Sundowns Club as well as the club name? A. MATCH (psn)-[:SUPPORTS]->(clb) WHERE clb.name = "Sundowns"

       RETURN psn, clb;
     B. MATCH (psn: Person)-[R]->(clb:Club)
       WHERE   (R = SUPPORTS) AND (clb.name = "Sundowns" )
       RETURN psn.name, clb.name
     C. MATCH (psn: Person)-[:SUPPORTS]->(clb:Club)
       WHERE  clb.name = "Sundowns"
       RETURN psn.name, clb.name
Show answer Study answer

C. It matches Person nodes with an outgoing SUPPORTS relationship to a Club, filters on the club name and returns the person's name and the club name. Option A returns whole nodes, not names. Option B uses R = SUPPORTS, which is not valid Cypher (the relationship type must be written [:SUPPORTS] or tested with type(R)).

MATCH (psn:Person)-[:SUPPORTS]->(clb:Club)
WHERE clb.name = "Sundowns"
RETURN psn.name, clb.name
Question 23 marksNeo4jPDF p.2 ↗

One limitation that is associated with relational database systems is that, due to normalization, information is obtained from the database through performing expensive joins of 2 or more tables. Explain how the Neo4j database system avoids this limitation.

Show answer Study answer

Neo4j stores relationships as first-class records that directly link a node to its neighbours (index-free adjacency). A query follows these stored links instead of computing a join between tables, so the cost depends on how much of the graph is traversed, not on the size of the tables. Highly connected data can be navigated without expensive joins.

Question 113 marksPostgreSQL ORDBMSPDF p.5 ↗

Suppose the following SQL statements have been executed on a PostgreSQL database:

   CREATE SEQUENCE venueSeq START 101;
   CREATE TYPE BuildingCodeType AS ENUM ('IT', 'LAW', 'CHM', 'PHY');
   CREATE TYPE RoomCodeType AS (building BuildingCodeType, floor int, room int);
   CREATE TYPE EquipmentType AS ENUM ('projector', 'PAsystem', 'safe', 'PC', 'phone');
   CREATE TABLE Venue (
           venueKey integer DEFAULT nextval('venSeq') PRIMARY KEY,
             venueCode RoomCodeType,
             seats int );
   CREATE TABLE LectureRoom (
             equipmentList text [ ] )
             INHERITS (VENUE);
   Which one of the SQL statements below will insert the data shown below into the
   LectureRoom table?

venueKey: auto-generated venue code: IT 4-2 seats: 120 equipment: projector, PAsystem, safe A. INSERT INTO LectureRoom ( venueCode, seats, equipmentList) VALUES ( ('IT', 4,2), 120, ['projector', 'PAsystem', 'safe'] ); B. INSERT INTO LectureRoom ( venueCode, seats, equipmentList) ( 'IT', 4,2, 120, ARRAY['projector', 'PAsystem', 'safe'] ); C. INSERT INTO LectureRoom ( venueCode, seats, equipmentList) VALUES ( ('IT', 4,2), 120, ARRAY['projector', 'PAsystem', 'safe'] );

Show answer Study answer

C. A row-typed value is written as ('IT', 4, 2) and an array with the ARRAY[...] constructor. Option A uses [...], which is not PostgreSQL array syntax. Option B has no VALUES and flattens the row type.

INSERT INTO LectureRoom (venueCode, seats, equipmentList)
VALUES (('IT', 4, 2), 120, ARRAY['projector', 'PAsystem', 'safe']);

As printed, the setup creates venueSeq but the default calls nextval('venSeq'), which would fail if you ran it. Treat that as a typo in the paper.

Show answer Study answer

B. xpath() returns an XML array; unnest() turns each array into a plain value so each staff member shows as a row of text. Option A would display arrays ({S010}), and C returns whole elements (with tags) instead of the text.

       unnest(xpath('/STAFF/NAME/FNAME/text()', staffData)) AS FirstName,
       unnest(xpath('/STAFF/NAME/LNAME/text()', staffData)) AS Surname
FROM XMLStaff;

Question 163 marksNeo4jPDF p.7 ↗

Another limitation that is associated with relational database systems is semantic overloading. This means that there is no mechanism to distinguish between relations and relationships or between different types of relationships. Explain how the Neo4j database system avoids this limitation.

Show answer Study answer

The property graph model separates nodes (entities) from relationships. A relationship is a first-class, named, directed connection with its own type (such as KNOWS or SUPPORTS) and properties. There is therefore a clear mechanism for telling relations from relationships and one type of relationship from another, which relational tables and foreign keys cannot express.

Question 183 marksNeo4jPDF p.7 ↗

Yet another limitation that is associated with relational database systems is that, schema changes are difficult. Database schema changes require program changes. Explain how the Neo4j database system avoids this limitation.

Show answer Study answer

Neo4j is schema-flexible: nodes, relationships and properties can be added or changed without altering a fixed table definition. New labels, relationship types and properties can be introduced without migrating existing data, so existing queries and programs keep working and schema changes do not force program changes.

Show answer Study answer

FALSE. This is not one of the OODBMS development strategies.
