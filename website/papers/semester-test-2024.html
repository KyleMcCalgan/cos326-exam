Question 2115 marksObject DBMS / JPAPDF p.12 ↗

Object DBMS

(a) Define the following terms

(i) OO data model.

(ii) OID

                                                       (4 Marks)

(b) Explain the differences between SQL and JPQL. With the aid of an example,

explain why JPQL is considered more “object-oriented” friendly than SQL. (4 Marks)

(c) You have the following JPQL query that retrieves all products with their associated categories:

Query q1 = em.createQuery("SELECT i FROM Invoice i JOIN i.customer c WHERE c.country = :country");

(i) Convert the above JPQL query to a using the JPA API in Java. TypedQuery Assume that Invoice is a JPA entity class and you want to retrieve a list of Invoice entities. (3 Marks)

(ii) Explain two key benefits of using over using a basic in JPA. TypedQuery Query (4 Marks)

Show answer Study answer

(a)(i) Object-oriented data model: a model that represents data as objects with identity, attributes (state) and methods (behaviour), organised in classes with inheritance, encapsulation and polymorphism.

(ii) OID (object identifier): a unique, system-generated identifier that identifies an object independently of its attribute values, used for references between objects.

(b) SQL works on tables, rows and columns and joins tables with foreign keys. JPQL queries entities and their attributes, navigating object relationships directly. Example:

SQL:  SELECT s.name FROM Employee e JOIN Supplier s ON e.supplier_id = s.id WHERE e.salary > 5000
JPQL: SELECT e.supplier.name FROM Employee e WHERE e.salary > 5000

JPQL navigates e.supplier.name using object references, with no join condition or table and column names, and it is independent of the storage schema.

(c)(i)

TypedQuery<Invoice> q1 = em.createQuery(
    "SELECT i FROM Invoice i JOIN i.customer c WHERE c.country = :country", Invoice.class);
q1.setParameter("country", country);
List<Invoice> invoices = q1.getResultList();

(ii) Two benefits of TypedQuery over a plain Query: (1) type safety: the result type is known at compile time, so you get List<Invoice> with no casting and errors are caught earlier; (2) cleaner code: no Object casts and better IDE support and readability.

(a) Completed function:

CREATE FUNCTION update_stock() RETURNS TRIGGER AS $$
DECLARE
    current_stock INT;
BEGIN
    SELECT stock INTO current_stock
    FROM inventory
    WHERE item_id = NEW.item_id;

    IF current_stock >= NEW.quantity THEN
        UPDATE inventory
        SET stock = stock - NEW.quantity
        WHERE item_id = NEW.item_id;

        IF current_stock - NEW.quantity < 5 THEN
            NEW.order_status = 'LowStockOrder';
        ELSE
            NEW.order_status = 'InStockOrder';
        END IF;

    END IF;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

(a) xpath() returns an XML array, so unnest it and cast to numeric if you want a number:

SELECT empId, empName,
       (xpath('/PERFORMANCE/RATING/text()', performanceData))[1]::text AS rating
FROM EmployeePerformance;

Result: E001 4.5, E002 4.8.
