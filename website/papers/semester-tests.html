JPA: transactions and rollback · 2025 Q21(b), p. 8

Begin a transaction before persistence operations, commit on success and roll back if an exception occurs. Only roll back an active transaction; handle the exception according to the application.

EntityTransaction tx = em.getTransaction();
try {
    tx.begin();
    // persist the evidence items
    tx.commit();
} catch (RuntimeException ex) {
    if (tx.isActive()) tx.rollback();
    throw ex;
}

Self-check: Does the example commit only after the operations succeed? Does it avoid rolling back an inactive transaction?

PostgreSQL: sum positive array elements · 2025 Q22(a), p. 8

Iterate over the array, add only positive values and return the accumulator. This assumes the input array and its elements are non-null.

CREATE FUNCTION sum_positive_changes(changes numeric[])
RETURNS numeric AS $$
DECLARE
    total numeric := 0;
    val numeric;
BEGIN
    FOREACH val IN ARRAY changes LOOP
        IF val > 0 THEN
            total := total + val;
        END IF;
    END LOOP;
    RETURN total;
END;
$$ LANGUAGE plpgsql;

For ARRAY[100, -50, 200, -30] the result is 300. A common mistake is to sum negative changes too.

PostgreSQL: update a derived value with a trigger · 2025 Q25(c-d), p. 12

A row-level BEFORE trigger can modify NEW and return it. This example assumes the referenced table and total_sales function already exist.

CREATE FUNCTION update_annual_sales() RETURNS trigger AS $$
BEGIN
    NEW.annual_sales := total_sales(NEW.sales_by_quarter);
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER update_sales_trigger
BEFORE INSERT OR UPDATE ON employees
FOR EACH ROW
EXECUTE FUNCTION update_annual_sales();

Self-check: A statement-level trigger does not receive a separate NEW row. An AFTER trigger cannot alter the row by returning a changed NEW.

XPath: find shipped-order customers · 2025 Q23(a-b), p. 9

Given an orders root containing order children, the predicate filters each order before selecting its customer:

/orders/order[status = 'Shipped']/customer
/orders/order[order_id = 203]/customer

The first selects customer elements for shipped orders; the second selects the customer element for order 203. Add /text() if text nodes are specifically required.

Cypher: match directed relationships · 2020 Q9, p. 3 and 2021 Q1, p. 1

Match a person and a club joined by an outgoing SUPPORTS relationship, then return their names:

MATCH (p:Person)-[:SUPPORTS]->(c:Club)
WHERE c.name = 'Sundowns'
RETURN p.name, c.name

Returning p, c returns nodes rather than only the requested name properties.
