ESSAY 1 · JPA · POSTGRESQL · XML · LECTURES 1–12 · 20 marks

Mixed practical: entity, trigger, XPath and XSD

An original question inspired by Semester Test 1 Q44, not a question from the test.

A research institute tracks Drone entities. Each drone has droneId, model, mission, maxAltitude and active, and has many SensorReading entities. A PostgreSQL table DroneEnergy(drone_id integer, stage_energy numeric[], average_energy numeric) holds a non-empty array of non-null values. XML has flight/flightCode, flight/status and flight/readings/reading/altitude.

  1. Write a JPA Drone entity with its ID, attributes and many readings. Write JPQL returning IDs of active drones with maxAltitude over 5000. Constructors and getters may be omitted. (7)
  2. Write a PL/pgSQL trigger function that loops through NEW.stage_energy, computes its average, assigns it to NEW.average_energy and returns NEW. Create the row-level BEFORE INSERT OR UPDATE trigger. (7)
  3. Write XPath returning altitude elements for readings above 3000, then an XSD fragment declaring flightCode as required text and status as text. (6)
Reveal model answer and marking points
// (a) Assume required imports and a valid SensorReading entity.
@Entity
public class Drone {
    @Id private int droneId;
    private String model;
    private String mission;
    private int maxAltitude;
    private boolean active;
    @OneToMany private List<SensorReading> readings;
}
SELECT d.droneId FROM Drone d
WHERE d.active = true AND d.maxAltitude > 5000

-- (b)
CREATE FUNCTION set_drone_average() RETURNS TRIGGER AS $$
DECLARE
    energy NUMERIC;
    total NUMERIC := 0;
    n INTEGER := 0;
BEGIN
    FOREACH energy IN ARRAY NEW.stage_energy LOOP
        total := total + energy;
        n := n + 1;
    END LOOP;
    NEW.average_energy := total / n;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
CREATE TRIGGER drone_average_trigger
BEFORE INSERT OR UPDATE ON DroneEnergy
FOR EACH ROW EXECUTE FUNCTION set_drone_average();

<!-- (c) XPath, followed by an XSD fragment -->
/flight/readings/reading[altitude > 3000]/altitude
<xs:element name="flightCode" type="xs:string" minOccurs="1"/>
<xs:element name="status" type="xs:string"/>

Self-mark: JPA: entity 1, ID 1, attributes 2, collection 1, JPQL 2. Trigger: function 1, iteration 2, average 2, assign and return 1, trigger 1. XPath: path and predicate 1, select altitude 1. XSD: flightCode declaration 1, text type 1, required 1, status text declaration 1. As in the original rubric, these are marking points; evaluate the whole answer for valid syntax.

ESSAY 2 · MONGODB · LECTURES 14–16 · 20 marks

MongoDB: library loans

A loans document has loanId, branch, status, daysLate, priority, an array staff of objects with role, and a string array tags.

  1. Find "Returned" loans over 7 days late, with a staff member whose role is "Librarian" and tag "overdue". Return loanId, branch and daysLate only. (5)
  2. Add "audit" to tags of all "High" priority loans without duplicates. (4)
  3. For returned loans, group by branch, calculate average daysLate and loan count, then sort by average descending. (7)
  4. For 3, 7, 10 and 12 days, calculate the average and decide whether it meets a maximum of 8 days. Show why. (4)
Reveal model answer and marking points
db.loans.find(
  { status: "Returned", daysLate: { $gt: 7 },
    "staff.role": "Librarian", tags: "overdue" },
  { _id: 0, loanId: 1, branch: 1, daysLate: 1 }
)
db.loans.updateMany({ priority: "High" }, { $addToSet: { tags: "audit" } })
db.loans.aggregate([
  { $match: { status: "Returned" } },
  { $group: { _id: "$branch", averageDays: { $avg: "$daysLate" },
              loanCount: { $sum: 1 } } },
  { $sort: { averageDays: -1 } }
])

Average = 32 / 4 = 8 days. Yes, 8 is at most 8. Mark as in Q34: 5 for the individual query requirements, 4 for the update, 7 for match/group/average/count/sort and 4 for calculation and justification.

ESSAY 3 · NEO4J · LECTURES 17–19 · 20 marks

Neo4j: field surveys

The graph contains (o:Observer)-[:RECORDED]->(s:Survey)-[:IDENTIFIES]->(b:Bird) and (s)-[:OCCURRED_IN]->(p:Park). Properties: observerId, survey confidence, birdId, bird species and park name.

  1. Return observer ID, bird ID and park name for surveys with confidence at least 0.8, species "Eagle" and park "North Park". (5)
  2. Return each matched observer's ID and survey count, highest count first. (6)
  3. Return each park name and the number of distinct birds identified there. (4)
  4. Return distinct bird IDs in North Park with confidence at least 0.8. Explain why a count of all qualifying surveys across all parks may differ. (5)
Reveal model answer and marking points
// (a)
MATCH (o:Observer)-[:RECORDED]->(s:Survey)-[:IDENTIFIES]->(b:Bird),
      (s)-[:OCCURRED_IN]->(p:Park)
WHERE s.confidence >= 0.8 AND b.species = "Eagle" AND p.name = "North Park"
RETURN o.observerId, b.birdId, p.name
// (b)
MATCH (o:Observer)-[:RECORDED]->(s:Survey)
RETURN o.observerId, count(s) AS surveyCount ORDER BY surveyCount DESC
// (c)
MATCH (s:Survey)-[:IDENTIFIES]->(b:Bird), (s)-[:OCCURRED_IN]->(p:Park)
RETURN p.name, count(DISTINCT b.birdId) AS birdCount
// (d)
MATCH (s:Survey)-[:IDENTIFIES]->(b:Bird), (s)-[:OCCURRED_IN]->(p:Park)
WHERE s.confidence >= 0.8 AND p.name = "North Park"
RETURN DISTINCT b.birdId

A survey count can count repeated surveys of the same bird and includes other parks if no park filter is applied. Mark the graph paths, filters and requested output as in Q35.

ESSAY 4 · PYSPARK · LECTURE 21 · 10 marks

PySpark: store revenue

Original practice, not a past-paper question: A file sales.csv has Store, Product and numeric Revenue. Read the file, calculate total revenue per store, and display the result. Explain how to find each store's highest individual revenue and the corresponding product. (10 marks)

Reveal model answer and marking points
from pyspark.sql import SparkSession
from pyspark.sql.functions import sum, max, col
spark = SparkSession.builder.appName("Sales Analysis").getOrCreate()
df = spark.read.csv("sales.csv", header=True, inferSchema=True)

totals = df.groupBy("Store").agg(sum("Revenue").alias("TotalRevenue"))
totals.show()

maxima = df.groupBy("Store").agg(max("Revenue").alias("MaxRevenue"))
d = df.alias("d")
m = maxima.alias("m")
top = d.join(m, (col("d.Store") == col("m.Store")) &
                (col("d.Revenue") == col("m.MaxRevenue")))
result = top.select(col("d.Store"), col("d.Product"), col("d.Revenue"))
result.show()

Group and sum for the total; group and take the maximum, then join on both store and maximum revenue to recover the product. Ties return multiple rows.

ESSAY 5 · DATA MINING · LECTURE 22 · 20 marks

Association rules: support and confidence

Five baskets: 1 Bread/Milk; 2 Bread/Milk/Juice; 3 Bread/Milk; 4 Bread/Juice; 5 Juice. Calculate support of {Bread, Milk} (4), confidence Bread ⇒ Milk (4), assess minimum support 60% and confidence 75% (4), calculate confidence Milk ⇒ Bread (4), and explain the result and a limitation (4).

Reveal model answer and marking points

Model answer: Both appear in 3 of 5 baskets, so support is 60%. Bread appears in 4 baskets: confidence Bread ⇒ Milk = 3/4 = 75%. Both thresholds are met. Milk appears in 3 baskets: confidence Milk ⇒ Bread = 3/3 = 100%. The rule describes association, not causation; five baskets are too few to confidently generalise.

ESSAY 6 · DATA WAREHOUSING · LECTURES 23–24 · 20 marks

Warehouse design and SQL

A retailer records each product sold, store, date, quantity and sales amount. (a) Design a star schema with a fact, three dimensions, keys and measures (6). (b) State the grain (2). (c) Write SQL for sales totals by province and category (4). (d) Add ROLLUP for province subtotals and the grand total (4). (e) A store moves province; preserve historical location (4).

Reveal model answer and marking points

Model answer: A sales fact at one sale-line grain has date, store and product foreign keys plus quantity and sales_amount. Date, Store and Product are dimensions. Join the fact to Store and Product, then use:

SELECT s.province, p.category, SUM(f.sales_amount) AS total_sales
FROM FactSales f
JOIN DimStore s ON f.store_key = s.store_key
JOIN DimProduct p ON f.product_key = p.product_key
GROUP BY ROLLUP(s.province, p.category);

Without ROLLUP, group by province and category for part (c). For part (e), use SCD Type 2: retain the old row and create a new row with a new surrogate key; old facts retain the old key.

ESSAY 7 · OLAP SQL · LECTURE 24 · 20 marks

Ranking and running totals

Monthly sales for Pretoria are 100, 150, 120 and Durban 80, 110, 130. Write a per-branch running total query (7), calculate Pretoria totals (3), rank branches by total sales (6), and explain RANK versus DENSE_RANK ties (4).

Reveal model answer and marking points
SELECT branch, month_no, sales_amount,
  SUM(sales_amount) OVER (PARTITION BY branch ORDER BY month_no
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running_total
FROM MonthlySales;

SELECT branch, SUM(sales_amount) AS total_sales,
  RANK() OVER (ORDER BY SUM(sales_amount) DESC) AS sales_rank
FROM MonthlySales GROUP BY branch;

Pretoria running totals are 100, 250 and 370; total 370 ranks ahead of Durban's 320. For 100, 90, 90, 80: RANK = 1,2,2,4; DENSE_RANK = 1,2,2,3.
