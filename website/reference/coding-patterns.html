Coding patterns

The shapes behind the code questions: the signal in the wording, then the steps that earn the marks. Drawn from the 2026 tests; open one to read it.

Object and relational · Lectures 1–8

Marked in Semester Test 1, Q44.

JPA: entity, collection and JPQL

Signal: "an object has many other objects" plus "query IDs satisfying conditions".

  1. Write @Entity, a class and exactly one appropriately typed ID.
  2. List every requested attribute once. Add @OneToMany and a collection of the related entity.
  3. Write JPQL against entity and attribute names. Select the requested property and join all required conditions.
  4. Check Java case, semicolons, types and missing conditions. For real execution, define the related entity and its mapping.
PL/pgSQL: derive a field from an array in a trigger

Signal: "recalculate whenever a row is inserted or updated".

  1. Declare a RETURNS TRIGGER function, the loop variable, sum and count.
  2. Use FOREACH ... IN ARRAY NEW.array_field LOOP; update sum and count for every value.
  3. Assign NEW.derived_field and RETURN NEW.
  4. Create a BEFORE INSERT OR UPDATE, FOR EACH ROW trigger that executes the function.
  5. Trace a short array and check the question's assumptions for empty arrays and nulls.

XML · Lectures 9–12

XPath and XSD from Q44; filtering, position and context from Test 2.

XML: filter a parent, return a child; declare schema elements

Signal: "depth of every reading where depth exceeds a threshold" means filter the reading and then select its depth. An XSD question asks for xs:element declarations and types; distinguish a fragment from a full schema.

/mission/readings/reading[depth > 3000]/depth
<xs:element name="missionCode" type="xs:string" minOccurs="1"/>
XPath/XQuery - Filter, position and keep context

Clues: "second item that satisfies a condition", or "each branch" where names repeat.

  1. Apply the predicate to the intended elements first.
  2. Use parentheses when the position should apply to the whole filtered sequence.
  3. When calculating per branch, bind the actual branch element and navigate relative to it rather than merging by name.
(//ITEM[HASH[@verified = "true"]])[2]/@caseId

Check: The second qualifying item is not necessarily the second item in the document. See Q10, Q13 and Q27.

MongoDB · Lectures 13–16

From Test 2, Q34. Operators are listed in MongoDB & indexing.

MongoDB - Filter documents and return selected fields

Clues: "find documents satisfying all conditions" and "return only these fields".

  1. Put all conditions in the first find object. Use dot notation for a property within an embedded document or array of documents.
  2. For a string array containing a value, use scalar equality. Use $elemMatch when several conditions must hold for the same array element.
  3. In the second object include requested fields with 1 and exclude _id with 0.
db.dispatches.find(
  { status: "Completed", responseTime: { $gt: 10 },
    "crew.role": "Paramedic", keywords: "cardiac" },
  { _id: 0, dispatchId: 1, station: 1, responseTime: 1 }
)

Check: Is the comparison strictly greater, are string values correctly capitalised, and did you exclude _id? See Q34(a).

MongoDB - Update all matching documents without duplicates

Clues: "all matching documents", "add to an array", "must not duplicate".

  1. Use updateMany and put the selection filter first.
  2. Put $addToSet in the update document and name the array and value.
db.dispatches.updateMany(
  { priority: "High" },
  { $addToSet: { keywords: "review-required" } }
)

Check: $push can add duplicates; $set replaces a field value. See Q34(b).

MongoDB - Summarise by group and filter totals

Clues: "for each station", "average", "count", or "groups whose total exceeds".

  1. Filter individual documents with $match if the condition applies before grouping.
  2. Use $group, with the group field in _id, named accumulators and $sum: 1 for a count.
  3. Filter calculated totals with a later $match; sort the resulting field with 1 ascending or -1 descending.
db.dispatches.aggregate([
  { $match: { status: "Completed" } },
  { $group: { _id: "$station", avgTime: { $avg: "$responseTime" },
              count: { $sum: 1 } } },
  { $sort: { avgTime: -1 } }
])

Check: Field references in expressions use $; filtering individual values before summing can change the total. See Q19, Q30 and Q34(c).

Neo4j · Lectures 17–19

From Test 2, Q35.

Cypher - Traverse a branched graph

Clues: a scenario lists node types and directional relationships and asks for properties from multiple nodes.

  1. Sketch each specified edge, including direction, before writing the query.
  2. Reuse the variable at the branching node; add conditions in WHERE.
  3. Return only requested properties, preserving their exact spelling and case.
MATCH (r:Ranger)-[:RECORDED]->(s:Sighting)-[:IDENTIFIES]->(rh:Rhino),
      (s)-[:OCCURRED_IN]->(v:Reserve)
WHERE s.confidence >= 0.90 AND rh.species = "Black Rhino"
  AND v.name = "Kruger National Park"
RETURN r.rangerId, rh.rhinoId, v.name

Check: The reserve edge begins at the sighting, not the rhino. See Q35(a).

Cypher - Count, deduplicate and filter groups

Clues: "per ranger", "different rhinos", "distinct IDs" or "groups with more than five".

  1. Match the relevant relationships; decide whether to count sightings or distinct rhinos.
  2. Return a non-aggregate field alongside count(...) to group by that field.
  3. For a list of unique IDs use RETURN DISTINCT rh.rhinoId; for a number use count(DISTINCT rh.rhinoId).
  4. To filter an aggregate, compute it with WITH, then apply WHERE.
MATCH (r:Ranger)-[:RECORDED]->(s:Sighting)
WITH r, count(s) AS sightings
WHERE sightings > 5
RETURN r.rangerId, sightings ORDER BY sightings DESC

Check: A count is a number, not the requested ID list; repeated sightings can represent one rhino. See Q25 and Q35(b–d).

Reading the question

Before you write, work out what the answer has to return.

Reading what a MongoDB or Cypher question wants back

For MongoDB, split the work into filter and projection, a targeted update, and aggregation stages. For Cypher, sketch directed edges first, then decide whether to return IDs, count sightings or count distinct entities.
