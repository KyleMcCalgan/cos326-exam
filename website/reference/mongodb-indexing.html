MongoDB syntax and indexing across languages

Find the right operator, query arrays of nested objects, and avoid confusing zero-based and one-based positions.

Nested arrays · Operators · Aggregation · Indexing across languages

Nested objects versus arrays of objects

{ patient: { municipality: "Tshwane" },
  crew: [ { name: "Thabo", role: "Paramedic" },
          { name: "Lerato", role: "Driver" } ],
  keywords: ["cardiac", "urgent"] }

A single nested object can be queried with { "patient.municipality": "Tshwane" }. An array of objects also supports dot notation: { "crew.role": "Paramedic" } matches if any crew member has that role. { keywords: "cardiac" } matches an array containing that scalar; { keywords: ["cardiac"] } asks for an exact array, not membership.

When two conditions must match the same element

db.dispatches.find({
  crew: { $elemMatch: { name: "Lerato", role: "Paramedic" } }
})

This does not match the example: Lerato is a driver. In contrast, { "crew.name": "Lerato", "crew.role": "Paramedic" } can match because different array objects satisfy the two conditions. Filtering finds whole dispatch documents; it does not automatically project only the matching crew member.

A particular element

db.equipment.find({ "inspections.1.inspector": "Amara" })

Array indexes start at zero, so .1 means the second inspection, as in Test 2 Q18. Without an index, the condition can match any inspection.

Useful query and update operators

Methods and operators have different jobs: updateMany(filter, update) chooses documents using its first argument and changes them using the second.

OperatorPurpose and example
$pushAdd an array value even if already present: { $push: { keywords: "urgent" } }.
$addToSetAdd only if absent: { $addToSet: { keywords: "urgent" } }. It does not remove existing duplicates.
$pullRemove all matching array elements: { $pull: { keywords: "outdated" } }.
$popRemove last with { $pop: { keywords: 1 } }, or first with -1.
$eachAdd multiple separate values: { $addToSet: { keywords: { $each: ["urgent", "review"] } } }. Without $each an array value is added as one element.
$set / $incAssign a field / increase a number: { $set: { status: "Completed" } }; { $inc: { responseTime: 2 } }.
$unset / $renameRemove a field / rename a field.
$all / $in{ keywords: { $all: ["cardiac", "urgent"] } } requires both; $in requires at least one listed value.
$size / $elemMatchMatch exact array length / require a single element to satisfy every listed condition.
$gt, $gte, $lt, $lte, $neComparisons: greater, greater-or-equal, less, less-or-equal, not-equal.
$existsCheck whether a field exists. A present field with null still satisfies $exists: true.
$or / $andCombine conditions. Fields in the same filter object are implicitly ANDed.

Exam Q34(b): MongoDB has no $append update operator. The question specifies no duplicates, so use:

db.dispatches.updateMany(
  { priority: "High" },
  { $addToSet: { keywords: "review-required" } }
)

Aggregation and cursor reference

$match filters; $group groups; $project shapes fields; $sort orders; $limit limits results; $unwind produces a pipeline row per array element. Inside a group, $sum, $avg, $min, $max and $addToSet are accumulators.

db.dispatches.aggregate([
  { $match: { status: "Completed" } },
  { $group: { _id: "$station", averageTime: { $avg: "$responseTime" },
              numberOfDispatches: { $sum: 1 } } },
  { $sort: { averageTime: -1 } }
])

Field references use a dollar sign; $sum: 1 counts matching documents. A post-group $match filters totals; filtering individual records before grouping can change the result.

hasNext() checks; next() retrieves and advances. Other useful methods include find, findOne, updateOne, updateMany, deleteOne, deleteMany, aggregate, sort and limit.

Indexing: which language starts where?

Language / contextFirstSecondExample
MongoDB array01"inspections.1.inspector"
Java array / List01readings[1] / readings.get(1)
Cypher list01readings[1]
PostgreSQL array1 normally2 normallyweekly_hours[2]
XPath / XQuery sequence12(//reading)[2]

PostgreSQL supports arrays with explicitly specified lower bounds; assume 1 only where ordinary arrays are used. SQL and JPQL result rows have no guaranteed order without ORDER BY. XSD minOccurs="1" is an occurrence count, not an array index.

Slices: PostgreSQL and Cypher differ

-- PostgreSQL, ordinary 1-based array [12,15,10,18]:
weekly_hours[2:3]  -- [15, 10]; both bounds included

// Cypher, zero-based list [12,15,10,18]:
hours[1..3]        // [15, 10]; end index excluded

Test 2 Q6 used PostgreSQL weekly_hours[2:3] and returned [15, 10]. Q18 used MongoDB's zero-based position: inspections.1 for the second inspection.

XPath position depends on context

(//reading)[2] selects the second reading in the resulting sequence; //reading[2] selects readings that are second children in their respective contexts. To take the second qualifying reading, filter first: (//reading[depth > 3000])[2].
