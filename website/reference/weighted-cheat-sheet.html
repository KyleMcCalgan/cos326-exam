PART A — NEWER CONTENT (PRIMARY FOCUS)

1. Lecture 11 — XQuery / FLWOR

1.1 The template to reproduce from memory

for $S in //STAFF
let $salary := $S/SALARY
where $S/@branchNo = "B004" and $S/SALARY > 15000
order by $S/STAFFNO ascending
return <RESULT>{ $S/NAME, $salary }</RESULT>
Feature Meaning / test trap
for $x in sequence Iterates: one binding per item. Produces a tuple stream.
let $x := expression Binds the whole result to a variable; no iteration by itself.
where ... Filters bound tuples; optional.
order by ... ascending/descending Sorts the surviving tuples; optional. Multiple keys are possible.
return ... Required; selects or constructs output once for each surviving tuple.
$S/@branchNo @ reads an attribute; $S/SALARY reads a child element.
{ $expr } inside <RESULT> Evaluates XQuery inside constructed XML; without {} it is literal text.
text() Selects text nodes, e.g. $S/NAME/LNAME/text().
$variable Case-sensitive ($S ≠ $s).
= vs eq = is a general comparison over sequences (true if any pair matches); eq is a value comparison expecting singleton operands.

Classic 1–3 mark tasks: write a FLWOR filtering salary and branch; list last names; put results in descending order; explain for versus let; or predict how many XML elements a return constructs.

1.2 Grouping, aggregate, some / every

(: one output per distinct branch :)
for $B in distinct-values(//@branchNo)
let $sal := //STAFF[@branchNo = $B]/SALARY
return <BRANCH>
         <CODE>{ $B }</CODE>
         <AVERAGE>{ avg($sal) }</AVERAGE>
         <COUNT>{ count($sal) }</COUNT>
       </BRANCH>
  • distinct-values(//@branchNo) = list of unique branch numbers.
  • avg(), sum(), count(), min(), max() summarise selected values. The node count and the count of salary elements can differ when XML is irregular.
  • some $x in $values satisfies ($x > 15000) = at least one satisfies the condition.
  • every $x in $values satisfies ($x > 15000) = all satisfy it.
for $B in distinct-values(//@branchNo)
let $S := //STAFF[@branchNo = $B]
where some $s in $S/SALARY satisfies ($s > 15000)
return <BRANCHNO>{ $B }</BRANCHNO>

Exam distinction: some is existential; every is universal. Do not confuse them with count() or distinct-values().

1.3 Join two XML documents: write the matching condition

for $S in //STAFF, $N in //NOK
where $S/STAFFNO = $N/STAFFNO
return <PAIR>{ $S/NAME, $N/NAME }</PAIR>

Walkthrough: (1) Two for bindings form candidate pairs; (2) where matches staff numbers; (3) return creates only matched pairs. Omitting where produces a Cartesian product. A correlated inner for inside an outer return can retain staff even when no next-of-kin record exists.

User-defined function skeleton (Lecture 11):

declare function local:double($n as xs:double) as xs:double {
  $n * 2
};
local:double(5)

2. Lecture 12 — XML inside PostgreSQL (SQL/XML)

2.1 Recognise the storage approach

Approach in slides What is stored Strength / weakness
1. Whole document in a column xml (PostgreSQL), historically CLOB Simple insert/retrieve; querying individual values may require parsing.
2. Shredded XML Elements distributed across relational columns/tables Individual elements indexable; must preserve/rebuild hierarchy.
3. Schema-independent / DOM Generic node/parent representation Flexible structure; tree reconstruction/querying more involved.
4. Parsed internal form DBMS internal representation Listed as the fourth approach; limited detail in slides.

2.2 SQL/XML statements worth memorising

CREATE TABLE XMLStaff (
  docNo CHAR(4) PRIMARY KEY,
  docDate DATE,
  staffData XML
);

-- Relational data -> constructed XML
SELECT XMLELEMENT(NAME staff,
         XMLATTRIBUTES(staffno AS id),
         XMLELEMENT(NAME salary, salary))
FROM Staff;

-- Relational query / table -> XML (PostgreSQL mapping functions)
SELECT query_to_xml('SELECT * FROM Staff', true, false, '');
SELECT table_to_xml('staff', true, false, '');
-- Schema alternatives: query_to_xmlschema(...), table_to_xmlschema(...)

Be able to distinguish: XMLELEMENT = create an element; XMLATTRIBUTES = attach attributes; query_to_xml / table_to_xml = produce XML from relations; *_xmlschema = produce an XML Schema description (not data rows).

2.3 Read XML with xpath() and flatten results

-- xpath() RETURNS xml[] (an array), even if only one item matches
SELECT xpath('/STAFF/STAFFNO/text()', staffData)
FROM XMLStaff;

-- [1] selects the first matching node; cast for numeric comparison
SELECT docNo
FROM XMLStaff
WHERE ((xpath('/STAFF/SALARY/text()', staffData))[1]::text)::numeric > 25000;

-- Multiple matching nodes -> separate SQL rows
SELECT docNo, unnest(xpath('/STAFF/SALARY/text()', staffData)) AS salary
FROM XMLStaff;

Trace in this order: SQL chooses table row → xpath(path, xml_col) locates nodes → result is xml[] → [1] selects array item, or unnest() returns a row per item. The slides also show server-side import helpers pg_ls_dir() and pg_read_file() for XML files; these require appropriate server permissions.

Likely exam question styles: identify which function generates an XML element; distinguish xpath() from unnest(); complete a query that filters extracted XML; identify shredded versus column storage.

3. Lecture 13 — Big Data, NoSQL and CAP (conceptual marks)

Five Vs: Volume (size), Velocity (speed/streaming), Variety (formats), Value (useful insight), Veracity (accuracy/trust). Examples in the slides: web clickstream/e-commerce/social networks, vehicle sensors, phones, stock markets and transport systems.

NoSQL = Not Only SQL; common reasons: flexible schemas, high write throughput, horizontal scaling, distributed processing. CAP: with a network partition, a replicated distributed system cannot guarantee both strong Consistency and Availability. Partition tolerance means continuing to deal with network splits. Availability prioritised during a partition can allow stale replicas; consistency prioritised can reject some requests. PACELC (flagged as student reading): if Partition, Availability vs Consistency; Else, Latency vs Consistency.

NoSQL model Think of Example / use
Key–value Lookup by a key Cache / session state
Document JSON-like flexible documents MongoDB, varying records
Wide-column Column families, sparse records Cassandra-style high-volume data
Graph Nodes, edges, relationship traversal Neo4j, social network
Time series Measurements indexed by time Sensor/telemetry records

False-statement traps: NoSQL does not mean “has no query language”; not all NoSQL systems guarantee eventual consistency; a graph relationship has a different role from a document field; MongoDB uses collections/documents, not tables/rows as its native terminology.

4. Lecture 14 — MongoDB CRUD, types and indexes

4.1 mongosh essentials + document shape

show dbs
use research
show collections
// db is the current database; collection = grouped documents
// An _id is generated if you omit it.
db.auvs.insertOne({ auvId: "A1", active: true, depth: 4200,
                    stages: [30, 45], contact: { city: "Durban" } })

Remember: database → collection → document → field; BSON supports strings, numbers, booleans, arrays, dates, embedded documents and ObjectId. Timestamp is primarily an internal BSON type; use Date for application dates. find() yields a cursor; findOne() yields one document.

4.2 The find() / projection / sort patterns

db.auvs.find({ active: true, depth: { $gt: 4000 } },
             { auvId: 1, depth: 1, _id: 0 }).sort({ depth: -1 })

// Two conditions OR'd; AND is implicit for separate fields.
db.auvs.find({ $or: [{ active: true }, { depth: { $gte: 5000 } }] })
db.auvs.find({ auvId: { $in: ["A1", "A3"] } })
Operator Meaning Operator Meaning
$gt > $gte >=
$lt < $lte <=
$ne != $in one of listed values
$and / $or logical conditions $eq equality

Test traps: first find argument = filter; second = projection. 1 includes, 0 excludes; generally cannot mix (except _id:0). .sort({depth:1}) ascending; -1 descending. MongoDB comparison operators start with $, unlike SQL comparators.

4.3 Updates, deletes, indexes

db.auvs.updateOne({ auvId: "A1" }, { $set: { active: false } })
db.auvs.updateMany({ active: true }, { $inc: { depth: 100 } })
db.auvs.deleteOne({ auvId: "A1" })
db.auvs.deleteMany({ active: false })
db.auvs.createIndex({ auvId: 1 })    // ascending index
db.auvs.find({ auvId: "A1" }).explain("executionStats")

$set changes a field; $inc increments a numeric field; updateOne vs updateMany and deleteOne vs deleteMany differ by how many documents can be affected. createIndex speeds appropriate lookups at write/storage cost; explain examines query execution.

5. Lecture 15 — MongoDB embedded data, arrays and aggregation

5.1 Nested documents and array traps

// Exactly matching an embedded document: field order/content matters.
db.users.find({ access: { level: 5, group: "dev" } })

// Preferred for one nested field: dot notation.
db.users.find({ "access.level": 5 })

// Array contains a value
db.students.find({ modules: "COS326" })

// ALL conditions on the SAME array element (not different elements)
db.sensors.find({ readings: { $elemMatch: { $gt: 30, $lt: 50 } } })

// Embedded documents in an array: conditions in ONE same document
db.orders.find({ lines: { $elemMatch: { item: "Cable", qty: { $gte: 2 } } } })

Critical distinction: {readings: {$gt:30, $lt:50}} can match when different array elements satisfy each condition. $elemMatch forces one single element to meet both. For an embedded object, "access.level" is not the same as matching the entire access object.

Cursor:

const c = db.users.find()
while (c.hasNext()) printjson(c.next())
// c.toArray() gets REMAINING documents: after full iteration, none remain.

5.2 Aggregation — the most useful write-and-trace template

Lecturer's seven blogs records, abbreviated:

Title likes values Group sum
NoSQL 400 400
MongoDB 100, 150, 50 300
Neo4j 50, 150, 250 450 
// SQL GROUP BY + HAVING + ORDER BY equivalent:
db.blogs.aggregate([
  { $group: { _id: "$title", total: { $sum: "$likes" } } },
  { $match: { total: { $gt: 300 } } },
  { $sort: { total: 1 } }
])
// Two outputs, in order: NoSQL 400; Neo4j 450.

Manually trace: (1) $group yields three totals 400/300/450; (2) $match on the computed total discards MongoDB 300 ($gt, not $gte); (3) $sort:1 orders 400 then 450.

Stage / accumulator Use
$match before $group Filter original documents (SQL WHERE).
$group: {_id:"$field", total:{$sum:"$value"}} Group by field and calculate total (SQL GROUP BY).
$match after $group Filter calculated group values (SQL HAVING).
$sort: {total:1} Ascending; -1 descending.
$sum, $avg, $min, $max Accumulators; $sum:1 counts members inside a group.
$project Transform/choose output fields.

A different question: “Total likes only for Neo4j?” Put { $match: { title:"Neo4j" } } first, then $group, and obtain 450. No $sort means the group order is not guaranteed.

5.3 Data-model design

  • Embed when children are bounded, accessed with their parent, and benefit from a single read (e.g. user's contact information).
  • Reference / normalise for large growing collections, complex many-to-many links, or excessive duplication (e.g. students and courses).
  • Common MCQ: embedding does not mean a relational foreign key is being created; referencing may require extra queries or joining logic.

6. Lecture 16 — MongoDB text search, shell functions, Java

// Text search requires a text index.
db.blogs.createIndex({ comments: "text" })
db.blogs.find({ $text: { $search: "big" } })
db.blogs.find({ $text: { $search: "big data" } })
// "big data" here means big OR data; default searches are case-insensitive.
// Entire phrase can be requested using escaped double quotes:
db.blogs.find({ $text: { $search: '"big data"' } })

// Wildcard text index; use cautiously (index size / write performance).
db.blogs.dropIndex("comments_text") // remove previous text index first
db.blogs.createIndex({ "$**": "text" }) // alternative index, not alongside it

Lecture dataset outputs: searching big finds the NoSQL blog (Big Data). Searching big data finds that blog and the Neo4j “social networks data” blog. Text search is not simple substring matching (data need not match database). A MongoDB collection supports at most one text index, which may cover multiple fields.

// $text in aggregate: $match containing $text MUST be the first stage.
db.blogs.aggregate([
  { $match: { $text: { $search: "NoSQL" } } },
  { $group: { _id: null, totalLikes: { $sum: "$likes" } } }
])

Client-side shell functions: written in JavaScript, possibly stored in .mongoshrc.js to load automatically in future shell sessions; not the same as server-side SQL stored procedures. db.getSiblingDB(dbName).getCollection(colName) accesses a database/collection by variables. Java MongoDB driver connects Java apps to MongoDB; Maven/Gradle manage driver dependencies (lecture mainly demonstrates setup / overview).

7. Lectures 17–18 — Neo4j graph concepts and Cypher

7.1 Theory: graph notation, direction, path weight

G = (V, E): V = vertices (nodes); E = edges (relationships). A directed edge (u,v) is not (v,u). A weighted edge (u,v,w) includes cost w. Path = connected sequence; cycle = starts/ends at same vertex with no repeated intermediate vertex; subgraph = subset of vertices and connecting edges.

Slide graph sample: V0 → V5 has weight 2; V5 → V2 has weight 1; V2 → V3 has weight 9; path V0 → V5 → V2 → V3 totals 12. Do not ignore arrow direction when adding path costs.

Property graph: Node has labels and key/value properties; relationships have a type, direction and may have properties (since:2017). Graph traversal uses relationship patterns, not SQL JOIN syntax.

7.2 Recognise and construct Cypher patterns

Pattern Meaning
(p:Person {name:'Thandi'}) Person node whose name is Thandi.
(a)-[:FOLLOWS]->(b) a follows b (outgoing from a).
(a)<-[:FOLLOWS]-(b) b follows a.
(a)-[:FOLLOWS]-(b) Relationship in either direction.
(a)-[r:FOLLOWS]->(b) Bind relationship to r, for r.since or DELETE r.
MATCH (p:Person) RETURN p.name Names of matched people.
MATCH (p:Person) WHERE p.age > 20 RETURN p.name Filter matched nodes.
ORDER BY p.name DESC Sort query results.

7.3 CREATE / MERGE / SET / REMOVE / DELETE

CREATE (t:Person {name:'Thandi', from:'Durban'}),
       (j:Person {name:'Johan', from:'Pretoria'}),
       (t)-[:FOLLOWS {since:2017}]->(j);

MATCH (p:Person {name:'Thandi'})
SET p.age = 21
RETURN p;

MERGE (p:Person {name:'Thandi'})
ON MATCH SET p.age = 22
ON CREATE SET p.from = 'Durban';

MATCH (p:Person {name:'Thandi'}) REMOVE p.age;
MATCH (a:Person {name:'Thandi'})-[r:FOLLOWS]->(b:Person {name:'Johan'})
DELETE r;                 // relationship removed; both nodes remain

MATCH (p:Person {name:'Johan'})
DETACH DELETE p;          // node AND ALL its relationships removed

Memorise differences: CREATE always creates; MERGE matches or creates a pattern; ON MATCH SET vs ON CREATE SET determine which branch runs; SET adds/updates a property; REMOVE deletes only a property/label; DELETE cannot remove a node still connected by relationships; DETACH DELETE also removes its relationships.

CREATE CONSTRAINT person_name_unique
FOR (p:Person) REQUIRE p.name IS UNIQUE;

7.4 Cypher aggregates and output tracing (lecturer's graph)

Assume three relationships: Thandi → Neo (2016); Thandi → Johan (2017); Johan → Thandi (2018).

MATCH (t:Person {name:'Thandi'})-[:FOLLOWS]->(f)
RETURN count(f) AS follows;                       // 2

MATCH (p:Person)-[r]->()
RETURN type(r) AS relationshipType, count(*) AS n; // FOLLOWS, 3

MATCH (p:Person)
RETURN collect(p.name) AS names;                  // list, 1 row

Trace: Thandi has 2 outgoing connections and 1 incoming; total 3 directed FOLLOWS relationships. count(*) counts matched rows; collect() produces one list; aggregation in Cypher groups implicitly by the non-aggregated returned expressions (no GROUP BY keyword). DISTINCT can avoid counting repeated values.

MATCH (p:Person)
OPTIONAL MATCH (p)-[:FOLLOWS]->(f)
RETURN p.name, f.name;

OPTIONAL MATCH keeps a person even if they follow nobody: their f.name is null (like a SQL left outer join). Plain MATCH with a relationship would omit that person. count(f) ignores null; count(*) counts retained rows.

Movie Graph homework pattern (Lecture 18):

MATCH (people:Person)-[rel]-(:Movie {title:'Cloud Atlas'})
RETURN people.name, type(rel), rel;

It finds connections of any type in either direction between a Person and that Movie; type(rel) reports labels such as ACTED_IN, DIRECTED, PRODUCED.

8.1 Object identity, persistence, and JPA / JPQL

  • OODBMS object identity (OID) is independent of values: two equal-valued objects can remain distinct. Logical OID is independent of storage location. Encapsulation combines state and behaviour. A persistent object survives program termination; semantic overloading is a relational-model weakness.
@Entity
public class Student {
    @Id private String studentNo;
    private String name;
    @OneToMany private List<Registration> registrations;
}

EntityManagerFactory emf = Persistence.createEntityManagerFactory("school.odb");
EntityManager em = emf.createEntityManager();
em.getTransaction().begin();
// assume s is an initialized Student entity with an ID
em.persist(s);
em.getTransaction().commit();
Student s2 = em.find(Student.class, "S123");

-- JPQL: ENTITY/class + JAVA attributes (not physical table/column names)
SELECT s.studentNo FROM Student s
WHERE s.active = true AND s.average > 65
-- Member in an entity collection: e MEMBER OF p.teamMembers

ST1 traps: @OneToMany must refer to a collection in the shown one-to-many model; JPQL generally doesn't use SELECT *; EntityManager operates on entities; EntityTransaction manages modifications; em.clear() detaches managed objects, so later changes may not be saved automatically.

8.2 PostgreSQL ORDBMS, arrays, procedures, triggers

CREATE TYPE Address AS (street TEXT, city TEXT);
SELECT (address).city FROM Customer;      -- composite field access
SELECT array_dims(stage_energy) FROM AUVEnergy;
-- PostgreSQL array subscripts are normally 1-based, not 0-based.

CREATE FUNCTION calculate_total() RETURNS TRIGGER AS $$
BEGIN
  NEW.total := NEW.quantity * NEW.unit_price;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER calculate_total_trg
BEFORE INSERT OR UPDATE ON OrderLine
FOR EACH ROW EXECUTE FUNCTION calculate_total();

ST1 traps: BEFORE trigger to alter the incoming row, always use NEW.column, then RETURN NEW. A function with IF/LOOP/WHILE/FOREACH ... IN ARRAY is commonly written in PL/pgSQL; DECLARE defines local variables; $1 is the first positional SQL-function parameter; RAISE EXCEPTION signals an error. array_dims(arr) reports dimensions, not array_dimensions().

8.3 XML, XPath and XSD basics

<!-- An XSD element containing children needs complexType + sequence. -->
<xs:element name="mission">
  <xs:complexType><xs:sequence>
    <xs:element name="missionCode" type="xs:string" minOccurs="1"/>
    <xs:element name="status" type="xs:string"/>
  </xs:sequence></xs:complexType>
</xs:element>

/mission/readings/reading[depth > 3000]/depth
//student[mark > 70]/name
//staff[@branchNo = 'B004']/NAME

Predicate placement is essential: [depth > 3000] belongs on reading, before /depth. @ marks an attribute; xs:simpleType is for simple-only content; xs:complexType can contain child elements; minOccurs="1" means required (default is 1 in a sequence). Namespaces avoid collisions.

10. One integrated mini-exam (practice, not an actual past-paper question)

Scenario: A research team stores mission logs in XML, vessel documents in MongoDB and personnel links in Neo4j.

(a) XML / 5 marks: Write a FLWOR query returning <ID> elements containing the ID of every MISSION whose DEPTH exceeds 3000, sorted by ID ascending.

for $M in //MISSION
where $M/DEPTH > 3000
order by $M/ID ascending
return <ID>{ $M/ID/text() }</ID>

Mark check (illustrative): correct for path (1); depth predicate (1); ordering (1); correct construction (1); ID content (1).

(b) MongoDB / 7 marks: Collection missions has vessel, status, and numeric energy. Return the total energy per vessel for only COMPLETED missions; show only vessels whose total > 100 in descending order of total.

db.missions.aggregate([
  { $match: { status: "COMPLETED" } },
  { $group: { _id: "$vessel", total: { $sum: "$energy" } } },
  { $match: { total: { $gt: 100 } } },
  { $sort: { total: -1 } }
])

Mark check: pipeline (1); initial status filter (1); group by correct field (1); sum (2); threshold after group (1); descending sort (1).

(c) Neo4j / 8 marks: Create a labelled Researcher node with name:'Lebo'. Find all researchers they collaborate with (outgoing COLLABORATES_WITH), return the names alphabetically, and provide a separate query counting the outgoing collaborations.

CREATE (:Researcher {name:'Lebo'});

MATCH (r:Researcher {name:'Lebo'})-[:COLLABORATES_WITH]->(other:Researcher)
RETURN other.name ORDER BY other.name ASC;

MATCH (r:Researcher {name:'Lebo'})-[:COLLABORATES_WITH]->(other)
RETURN count(other) AS collaborations;

Mark check: label + property + CREATE (2); correct direction and type (2); projecting collaborator names (1); sorting (1); count query (2). Total = 20 practice marks.
